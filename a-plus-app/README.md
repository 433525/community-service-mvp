# 社区服务项目：本地 MVP

当前仓库提供两个独立入口：A+ 内部受理流程，以及覆盖首页、社区、发布、消息、我的五栏的社区服务交互原型。两者都只使用合成数据并保存在当前浏览器，不是可接入实际运营的系统；通用服务类型暂记为“待判定/未分类”。

## 运行

```bash
npm install
npm run dev
```

构建：

```bash
npm run build
```

## 社区服务五栏 MVP（`/community.html`）

- 首页：查看演练动态摘要、安全说明，并跳转到通用求助、志愿发布或邻里分享。
- 社区：按类型筛选、搜索动态，并对合成帖子点赞、收藏和评论。
- 发布：登记通用求助、志愿记录/活动招募、邻里分享；活动可设置开始时间和名额，可切换匿名与是否显示在社区动态。
- 消息：查看本人求助及按来源 ID 匹配的 A+ 本机受理进度，查看合成系统通知，试写本机聊天与自动回复，保存未提交的本机反馈。
- 我的：查看发布、收藏、求助记录和只读演示账本；“服务记录”可只读显示 A+ 工作台中按来源帖子匹配的受理状态和最近更新时间，支持手动刷新，并在切回页面时重新读取。已结束记录重开后，进度会跟随最新关联记录。
- 社区页面状态独立保存在浏览器 `localStorage`；重置会覆盖本机新增的演练内容，并为种子帖子生成新 ID，避免旧 A+ 记录串到重置后的内容。
- 多个标签页同时打开时，检测到存档已变化会暂停写入；到“我的”页重新载入最新存档后可继续操作。
- 点赞、评论、求助“接单”、活动报名和聊天都只是本机状态演示；消息自动回复为虚构内容，时间账本只读，不提供真实履约或兑换结算。
- 不会向居民、志愿者、管理员或外部机构投递消息，也不提供真实紧急求助、定位、身份核验或运营后台。

打开 `community.html` 进入五栏原型；打开 `/` 进入 A+ 内部受理原型。两者使用不同的本机存储记录。

## A+ 内部受理 MVP（`/`）

- 通用服务登记演练，默认服务类型为“待判定/未分类”。
- 新建记录时仅按标签或摘要的完全重复提示候选（忽略首尾空白、折叠连续空白和大小写，不做模糊匹配）；发现候选会暂停创建并列出候选记录，只有人工再次确认并填写复核说明后才能另建独立记录。新记录保留原表单字段、关联候选并追加复核时间线，不合并、覆盖或删除候选。
- 每条记录带“来源渠道演练标记”（人工录入演练 / 社区入口演练（仅本机） / 其他虚构来源），新建记录默认人工录入演练；该标记只用于比较合成来源，不会创建或连接真实居民入口、社区渠道或外部服务。缺少该字段的旧本机记录和 v1 备份显示为“历史来源未记录”，不会被拒绝或自动补写。
- “社区求助（本机演练）”入口会手动、单向读取社区演练存档中开放或已被本机演练接单的合成求助；逐条点击后通过现有创建流程登记到 A+ 队列，重复点击不会新建记录。记录可持久化可选的 `sourcePostId`，详情可辨识来源帖子 ID，新导出/导入会保留该字段。社区存档缺失、损坏或版本不兼容时只显示空态/错误，不写回、不重置任何一端存档。
- 内部受理队列、状态筛选、演练逾期与高风险停止提示。
- 初筛、待补充、受理分诊、转介确认和转介失败后的分诊恢复。
- 常规初筛与信息补充前须先确认演练同意；普通接单、转介、跟进及模拟联系还要求必填信息已标记完整。请求补充信息不要求信息已完整；高风险人工交接和安全退出仍可使用。检查点只控制本机合成流程，不代表真实法律同意或服务授权。
- 转介接收仍保持待跟进；可用专用原因和说明结束人工跟进，且明确标记服务结果未核实。
- 开放记录可随时追加高风险停止初筛标记；标记后锁定普通初筛、联系模拟和状态操作，仅保留可反复登记的演练人工交接。每次交接记录“有人接手 / 暂无人接手”、负责人、下一步和截止时间；有人接手时另记虚构接手人。
- 可切换受理、复核和转介演示角色；后续时间线记录会显示当前角色，切换仅用于流程演练，不提供真实身份验证或权限控制。
- 转介登记要求填写虚构演练对象和依据；转介确认/失败均只更新本地演练记录。
- 追加式跟进记录、模拟联系结果记录，以及高风险情形的可重复演练人工交接记录。
- 已结束记录可建立新的关联演练记录；原记录和时间线保留。
- 内置演练数据为合成案例；修改会保存到当前浏览器，刷新后可继续演练。
- 支持导出 JSON 全量备份，以及校验后导入并完整替换当前演练记录；也可恢复初始演练数据。
- 存档状态、最近保存时间会显示在页面提示栏；无法读取的旧存档不会被自动覆盖，可先下载原文再恢复初始数据或导入备份。
- 本机存储不可用时会提示记录只保存在当前会话；存档写入失败时会阻止本次修改，避免界面显示未落盘的数据。

### A-03 跨合成来源重复候选演练

1. 在“新建演练记录”中使用相同的标签或摘要，来源渠道分别选择“人工录入演练”和“社区入口演练（仅本机）”。
2. 第二次创建会暂停并列出完全重复候选；对照候选记录旁的来源渠道与本次拟建记录的来源，填写人工重复复核说明后确认另建独立记录。
3. 在登记队列、记录详情和重复候选列表中核对两条记录各自保留的来源；导出的 JSON 备份应包含 `sourceChannel` 字段。
4. 旧本机记录或旧 v1 备份若没有该字段，会显示“历史来源未记录”；不会被拒绝、补写或猜测来源。

“社区入口演练（仅本机）”只是本机合成来源标签，不是真实社区入口；演练不会创建或连接任何真实受理渠道。

### A-04 社区求助本机单向桥演练

1. 使用内置合成求助，或发布一条求助并保持为“开放”；也可以先对他人发布的合成求助演练接单。
2. 回到 A+，点击“社区求助（本机演练）”，手动读取社区存档；页面列出开放或已被本机演练接单的合成求助，并标出社区状态和 A+ 已登记状态。
3. 逐条点击“登记到 A+ 队列”。若标签或摘要命中现有记录，会暂停并列出候选；必须勾选已核对、填写复核说明并再次确认，才会创建独立记录。
4. 登记只在 A+ 追加记录并保存 `sourcePostId`；不会写回社区帖或改变其接单/开放状态。重复点击同一帖子不会新建记录。
5. 社区存档缺失、损坏或版本不兼容时会显示说明；两端存档都不会被覆盖或重置。
6. 回到社区页“我的 → 服务记录”或“消息 → 服务进度”，刷新后可看到本人发布或演练接单求助的社区状态，以及按来源 ID 匹配的 A+ 演练状态和更新时间；页面仅读取 A+ 合成存档，不显示受理备注，也不向居民端或外部渠道发送通知。

## 使用边界

- 数据以明文保存在当前浏览器的 `localStorage`，不调用服务端；不提供登录、真实权限控制、服务端审计或加密存储。清理浏览器数据、换浏览器或换设备时，数据不会自动迁移。
- A+ 的 JSON 导入会先校验格式、版本、字段、时间线和记录关联，再整体替换 A+ 演练数据；导入失败时保留当前数据。v1 旧备份继续兼容，重复复核时间线字段、候选关联、来源渠道（可缺省以保留历史记录）、可选社区来源帖子 ID 以及人工交接结果/虚构接手人字段也会校验；不含来源渠道、社区帖子 ID 或交接新字段的历史 v1 记录仍可导入。新导出会保留已存在的 `sourcePostId`，缺失时不会补写。导出文件可能包含全部演练文本，请只使用虚构数据并保存在受控位置。社区五栏没有 JSON 导入导出。
- 本原型不提供单条记录删除、正式纠错审批、权限隔离或可靠的生产备份机制；浏览器本机存储与手动 JSON 文件均不能替代生产系统的数据治理和备份。
- 表单包含自由文本字段，当前原型没有识别或阻止真实个人信息的技术能力。只能输入虚构内容，不得输入真实居民的姓名、电话、地址、健康或儿童信息。
- 页面中的创建、状态、跟进和模拟联系操作只修改本机的合成演练数据，并在对应记录的时间线追加角色、时间和说明；模拟联系结果不改变登记状态，也不会产生真实外部效果。
- “结束人工跟进”只结束演练队列中的待办，不表示服务已经提供、完成或核实；结束记录仍可建立关联演练记录。
- 本原型不会发送通知、联系外部机构、派单或调度救援。转介和高风险人工交接只记录演练输入，不代表外部机构真实接收、升级已完成或风险已解除。
- 高风险记录会停止常规初筛，并允许反复登记演练人工交接结果；交接记录中的“有人接手”仅表示本次演练登记，不代表真实人员已接手、风险已解除或服务已完成。该演示没有后续升级工作流，不构成完整的高风险运营处置方案。
- 页面里的演示角色只用于展示，不构成身份验证或授权。
- 默认跟进截止时间仅是演练值，不构成运营 SLA。
- 不要用于真实服务受理、值守或业务决策。接入实际运营前，须由有权运营方完成范围授权、数据治理、人员和值守安排、身份权限、部署、安全及备份恢复验收。
