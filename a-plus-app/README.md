## B 受控社区 MVP（`/community.html`）

用户于 2026-10-21 选择截图中的方案 B；该决定替代此前“先完成 A+ 真实试点再开发 B 原型”的顺序。当前仍为本地合成数据原型。

- 首页与社区：仅展示审核通过且公开的求助、志愿、邻里内容，支持搜索和筛选。
- 首页公告轮播：「邻里公告板」五条合成公告，支持自动播放、前后/圆点/方向键/滑动切换与播放暂停；焦点进入即停止且不自动恢复，`prefers-reduced-motion` 下默认不播放；非当前幻灯片 `aria-hidden` + `inert`，切换不产生页面回流。
- 成员准入：演示访客、已核验成员、审核员三种身份；访客看不到社区正文，成员才能发布和互动。身份切换无认证能力，不采集真实证件或邀请码。
- 发布和评论：新内容进入待审队列，审核通过后展示；本人发布可在“我的”查看状态与审核意见。旧存档缺少审核状态的内容进入待审。发布表单自动保存本机草稿：离开发布页或刷新后可恢复，但“虚构内容确认”不会被恢复，提交前必须重新勾选；发布成功或手动“清除草稿”后删除。
- 求助订单履约演练：求助单有 `待接单 → 已接单 → 待确认完成 → 已完成`，另可取消/关闭，或发起争议后撤销/关闭；每一步都写入该帖的订单事件时间线并保存在本机。本机参与者只能操作自己一侧；为演示双方流程，提供明确标注“代合成对方”的按钮，页面注明对方是合成演练对象，不会产生真实接单、履约、双方确认或结算。审核员下架进行中的求助时，本机订单会自动关闭并记录 `cancel/审核员` 事件与参与者通知。
- 审核备注可见性：`reviewNote` 只在审核页和本人“我的发布”展示，不再出现在公开社区卡片；同一目标已有待处理举报时重复提交会提示已有记录，不显示为成功。审核页顶部提供待审发布/待审评论/待处理举报/订单留言四张实时计数卡，点击跳到对应区块并聚焦；审核页支持四组筛选：内容按全部/待审/通过/下架/驳回，评论按待审/通过/驳回/下架/全部，举报按待处理/已处理/不予支持/全部，订单留言按全部/未下架/已下架，均带计数；顶部搜索框可跨四类列表与审核日志叠加过滤（仅页面内存）；审核日志还可按动作筛选并记住本机偏好。筛选会记住在本机浏览器（`community-mvp.moderation-filters.v1`，与审核存档分离），可一键重置。
- 订单完成会生成一条“未结算”的演示时长记录，进入“我的 → 时间账本”；它没有双方真实确认，不可兑换、结算或提现。完成后发布者或接单成员可给这次本机演练留一条 1–5 星体验记录（说明可选，同一订单一次），只保存在当前浏览器，不发送评价、不影响真实信誉；只有参与者能在卡片看到摘要，也可在“我的 → 服务记录”查看。服务记录支持“有体验”筛选并显示体验条数与平均星级。

- 订单留言：自由私聊关闭；仅审核通过、公开、本人参与且进行中的求助可留言；订单完成或关闭后留言只读。不生成自动回复。

### B 求助订单履约演练（本机双人流程代演）

1. 切换为“演练成员”，在社区找一条审核通过的他人求助，点“演练接单”。也可以发布自己的求助，审核通过后点“代合成邻居接单（演练）”。
2. 接单后，本机接单成员一侧点“发起完成申请”；求助发布者一侧点“代合成接单方申请完成（演练）”。
3. 对方确认：本机接单成员点“代合成求助方确认完成（演练）”；求助发布者点“确认完成”。两种路径都会把订单记为“已完成（本机演练）”，并生成一条“未结算”演示时长。
4. 进行中的订单可填写原因后“取消/关闭订单”或“发起争议”；争议中可“撤销争议继续履约”或“因争议关闭订单”。完成与关闭后的订单留言为只读。
5. 全程只修改当前浏览器中的合成数据；合成对方按钮仅用于补齐双人流程演示，不会联系真实居民、不会发送通知、不会产生真实履约或结算。旧存档中已接单但没有事件时间线的订单会显示“无法还原历史步骤”，后续操作从当前状态继续记录。

### A-03 跨合成来源重复候选演练

1. 在“新建演练记录”中使用相同的标签或摘要，来源渠道分别选择“人工录入演练”和“社区入口演练（仅本机）”。
2. 第二次创建会暂停并列出完全重复候选；对照候选记录旁的来源渠道与本次拟建记录的来源，填写人工重复复核说明后确认另建独立记录。
3. 在登记队列、记录详情和重复候选列表中核对两条记录各自保留的来源；导出的 JSON 备份应包含 `sourceChannel` 字段。
4. 旧本机记录或旧 v1 备份若没有该字段，会显示“历史来源未记录”；不会被拒绝、补写或猜测来源。

“社区入口演练（仅本机）”只是本机合成来源标签，不是真实社区入口；演练不会创建或连接任何真实受理渠道。

### A-04 社区求助本机单向桥演练

1. 使用内置合成求助，或发布一条求助并保持为“开放”；也可以先对他人发布的合成求助演练接单。
2. 回到 A+，点击“社区求助（本机演练）”，手动读取社区存档；页面列出开放或已被本机演练接单的合成求助，并标出社区状态和 A+ 已登记状态。
3. 逐条点击“登记到 A+ 队列”。若标签或摘要命中现有记录，会暂停并列出候选；必须勾选已核对、填写复核说明并再次确认，才会创建独立记录。
4. 登记只在 A+ 追加记录并保存 `sourcePostId`；不会写回社区帖或改变其接单/开放状态。重复点击同一帖子不会新建记录。
5. 社区存档缺失、损坏或版本不兼容时会显示说明；两端存档都不会被覆盖或重置。
6. 回到社区页“我的 → 服务记录”或“消息 → 服务进度”，刷新后可看到本人发布或演练接单求助的社区状态，以及按来源 ID 匹配的 A+ 演练状态和更新时间；页面仅读取 A+ 合成存档，不显示受理备注，也不向居民端或外部渠道发送通知。

## 使用边界

- 数据以明文保存在当前浏览器的 `localStorage`，不调用服务端；不提供登录、真实权限控制、服务端审计或加密存储。清理浏览器数据、换浏览器或换设备时，数据不会自动迁移。
- A+ 的 JSON 导入会先校验格式、版本、字段、时间线和记录关联，再整体替换 A+ 演练数据；导入失败时保留当前数据。v1 旧备份继续兼容，重复复核时间线字段、候选关联、来源渠道（可缺省以保留历史记录）、可选社区来源帖子 ID 以及人工交接结果/虚构接手人字段也会校验；不含来源渠道、社区帖子 ID 或交接新字段的历史 v1 记录仍可导入。新导出会保留已存在的 `sourcePostId`，缺失时不会补写。导出文件可能包含全部演练文本，请只使用虚构数据并保存在受控位置。社区五栏只提供本机存档 JSON 只读查看与复制（打开时快照，含订单事件），不提供导入或上传。
- 本原型不提供单条记录删除、正式纠错审批、权限隔离或可靠的生产备份机制；浏览器本机存储与手动 JSON 文件均不能替代生产系统的数据治理和备份。
- 表单包含自由文本字段，当前原型没有识别或阻止真实个人信息的技术能力。只能输入虚构内容，不得输入真实居民的姓名、电话、地址、健康或儿童信息。
- 页面中的创建、状态、跟进和模拟联系操作只修改本机的合成演练数据，并在对应记录的时间线追加角色、时间和说明；模拟联系结果不改变登记状态，也不会产生真实外部效果。
- “结束人工跟进”只结束演练队列中的待办，不表示服务已经提供、完成或核实；结束记录仍可建立关联演练记录。
- 本原型不会发送通知、联系外部机构、派单或调度救援。转介和高风险人工交接只记录演练输入，不代表外部机构真实接收、升级已完成或风险已解除。
- 高风险记录会停止常规初筛，并允许反复登记演练人工交接结果；交接记录中的“有人接手”仅表示本次演练登记，不代表真实人员已接手、风险已解除或服务已完成。该演示没有后续升级工作流，不构成完整的高风险运营处置方案。
- 页面里的演示角色只用于展示，不构成身份验证或授权。
- 默认跟进截止时间仅是演练值，不构成运营 SLA。
- 不要用于真实服务受理、值守或业务决策。接入实际运营前，须由有权运营方完成范围授权、数据治理、人员和值守安排、身份权限、部署、安全及备份恢复验收。
