# 调研与实现发现

## 已确认

- 当前项目是 Vue 3 + Vite 本地合成数据原型，有社区入口与 A+ 受理入口两套独立页面。
- 社区求助可通过人工操作导入 A+；A+ 记录保留 `sourcePostId`，且工作台可记录初筛、转介、跟进等状态事件。A+ 读取器接受全部六种本机订单状态（open/accepted/completion-requested/completed/cancelled/disputed）并只展示状态标签；此兼容修复在本轮新增状态后完成，避免旧读取器把新状态整份判为无效。
- A+ 使用 `a-plus.synthetic-intake.v1` 保存数据；`parseIntakeBackup` 能校验导出的合成演练备份格式。
- 社区“我的/服务记录”和“消息/服务进度”现在通过只读投影按来源帖子 ID 显示 A+ 状态、最近事件和更新时间；不展示内部备注、负责人或下一步。消息页不再把固定种子状态线程当作当前进度。
- 求助订单有本机履约演练状态机：open → accepted-local-demo → completion-requested → completed-local-demo，另有 cancelled-local-demo、disputed-local-demo 与争议撤销/关闭；每步追加 `Post.orderEvents` 事件（类型、本机参与者/合成对方、说明、时间），并显示在社区卡片、我的服务记录和消息订单中。
- 双人流程用明确标注的“合成对方（代记录）”按钮补齐：求助发布者侧可代合成邻居接单、代合成接单方申请完成并本机确认；本机接单成员侧可申请完成并代合成求助方确认。页面与 README 均说明对方是合成演练对象，不会通知真实居民。
- 订单完成会在时间账本追加一条“未结算”的演示时长记录（从 `duration` 文本估算分钟数，无法估算时保守给 30 分钟）；没有结算、兑换、提现或真实双方确认。
- 本人内容审核结果、合成对方订单动作、本人订单留言被下架会向本机 system 线程追加通知；通知只在本浏览器，不是真实消息投递。
- “我的”页可查看打开时的本机存档 JSON 只读快照并复制；社区仍不提供导入或上传。
- `signUpForEvent` 已要求 `volunteerKind === 'activity'`，普通志愿记录/邻里/求助不能通过共享函数报名；新增 `cancelEventSignup` 只有活动招募且有本机报名时可取消。旧存档缺少 volunteerKind 的记录按“非活动”处理，不会猜测补写。
- 大字阅读偏好（`community-mvp.reading-mode.v1`）与发布草稿（`community-mvp.publish-draft.v1`）都是独立的本机 UI 数据，不写入社区存档 envelope；草稿不恢复“虚构内容确认”，提交前仍必须人为勾选。
- 未读通知使用 `CommunityState.notificationsReadAt` 字符串比较（ISO 时间）；`persistState` 会对缺少该字段的局部状态快照做回填，避免每次订单/审核写入清空已读游标。旧存档载入时以历史最后一条 system 通知为已读游标。
- 举报记录新增可选 `reporter`；同一举报人同一目标已有待处理举报时去重，创建举报会写入 `create-report` 审核日志。旧存档举报没有 `reporter` 时显示“历史举报人未记录”，不回填、不推测。
- 系统通知未读计数与 `document.title` 前缀只依赖本机存档；标为已读会写存档，因此刷新后角标状态保持。
- 使用说明与首页安全说明弹层实现了键盘行为：打开时焦点进入弹层、Tab 在弹层内循环、Esc 关闭并归还焦点、点遮罩关闭；移动端帮助弹层为单列且宽度适配 390px。
- “我的 → 服务记录”筛选状态只影响展示，不修改订单；展开订单事件只改变展示条数。服务记录按本机订单状态分桶：completed=已完成，cancelled=已关闭，其余（open/accepted/completion-requested/disputed）=进行中。
- 管理链路实测：进行中订单留言可发送，审核员下架后成员端不再显示但审核端保留原文与 `hide-message` 日志；处理举报写 `resolve-report` 日志与处理说明；下架帖子后可“恢复为通过”并写 `moderate-post` 日志。以上均为本机合成演练，无真实消息投递或内容处置。
- “我的活动”读取 `signedUpByMe=true` 的活动帖（含审核/公开状态），取消调用共享 `cancelEventSignup`；活动在社区卡片、我的活动和报名计数间保持一致，取消后列表移除。
- 键盘跳过链接是页面首个可聚焦元素，聚焦时可见，激活后焦点进入 `<main id="community-main">`（带 `tabindex="-1"`）；不改变数据。
- A+ 社区登记链路已实测：社区审批通过的求助可在 A+ 面板勾选合成确认后登记，生成 `sourcePostId` + `sourceChannel=community-entry-local` 的 A+ 记录；登记不写回社区存档；重新打开按来源帖识别“已登记”，不会重复创建。
- A+ 读取器容错实测修复：单条审核通过记录字段损坏时不再整份失败，改为跳过并在面板显示 `warnings` 与“已读取 N 条…跳过 M 条”状态；重复帖子 ID 同样跳过并警告；只有存档级问题（非 JSON/版本/结构/超限）整份失败。原文不写回、不修复。
- 社区存档导出→写回→重载往返通过：含 `orderEvents`、`reporter`、`notificationsReadAt` 的状态可被自身校验接受；删除这些字段的旧档仍可载入，已读游标按最后一条历史通知补齐，旧订单事件/举报人保持缺失不补写。
- A+ 登记后社区“服务记录”可显示 A+ 状态（已收件）与最近事件；A+ 重复登记的人工复核分支实测通过：需勾选 + 复核说明，创建独立记录并带 `duplicate-review` 事件与候选关联。
- A+ 社区桥读取器当前按“单条容错、存档级严格”处理：社区页自身遇到损坏存档仍进入 recovery-required 并保留原文，这是有意的原文保护，不是 A+ 读取器能修复的范围。
- 修复批次二：审核备注 `reviewNote` 只在审核页/本人发布处展示；重复举报返回 `already` 时界面提示“已有一条待处理的本机举报”；审核下架进行中求助会自动把订单置为 cancelled 并追加 `cancel/审核员` 事件与参与者通知；订单事件超过 100 条时 `persistState` 拒绝写入，避免生成自身无法读取的存档。
- A+ 侧修复：`community-entry-local` 必须带社区帖子 ID，非社区来源不得带帖子 ID（新建与备份导入均校验，导入拒绝空摘要）；投诉提交时若没有可用复核角色（提交人/被投诉角色占用了 review/referral）直接拒绝；导入成功后关闭备份文本面板；存在无法读取旧存档时，必须先下载原文才允许重置或导入；筛选/搜索变化后若当前详情不在结果中会自动选中首条结果。
- A+ 弹层统一键盘行为：打开焦点进入、Tab 循环、Esc 关闭、焦点归还触发按钮；隐藏文件输入移出 Tab 序列；`main` 提供跳过链接锚点；焦点环改为实色 `#176c69`。移动端 390px 修复横幅正文列被按钮挤压、底部导航裁切与标题区操作按钮隐藏。
- B 端移动端：顶栏说明/大字/消息按钮 ≥44px、主按钮 ≥44px、大字模式顶栏不重叠、“我的”5 个 tab 自动换行；少量次要文字颜色加深，审核理由空值增加内联 alert 与 aria-required/aria-invalid。
- 修复三批复验：旧存档无事件时仍可确认完成（completed + 事件）；订单事件到 100 条时第 101 条被 persistState 拒绝且刷新后存档仍 saved；通知文案指向社区卡片、服务记录提供“去社区动态处理”；A+ 不可读旧存档必须先下载原文才允许重置/导入。
- 采纳落地：B 说明弹层打开时 topbar/app-frame/mobile-nav 设置 `inert`；A+ 任一弹层打开时侧栏与主内容 `inert`，关闭恢复；未引入依赖。背景 `inert` 与前面的焦点进入/Tab 循环/Esc/归还共同构成弹层可访问性基线。
- 设计 Token 首轮落地：两套样式表新增 `--text-body/--text-title/--text-small/--tap-min/--focus-ring/--radius-card/--ease-out`；B 桌面正文 14px、标题 17px，移动端正文 14px/标题 18px；A+ 桥正文 13px、状态 12px、脚注 11px，移动端输入 16px。Token 为增量迁移基线，尚未全站替换。
- A+ 新建表单已补 required/aria-required（摘要/来源/负责人/截止/下一步），摘要通过 `aria-describedby` 关联 `create-record-error`，错误容器 `role=alert`；自定义校验逻辑不变。
- 次级文字迁移：B 页脚/账本/通知/订单时间线/线程副标题/存档说明用 `--text-small`（12px），线程标题/审核标记/服务记录正文 13px，聊天与帮助正文 14px；A+ 顶部登记说明 12px，风险/候选/合成确认/检查点/错误 11–12px。
- 错误播报：B/A+ toast 根据文案命中错误关键词切换 `role=alert` + `aria-live=assertive`，普通成功保持 `status`/`polite`。该分类是过渡方案，后续可改为显式 tone 参数，避免“成功消息含上限提示”等边界误判。
- 首页“我的待办”三张卡直接读取 store：进行中订单（accepted/completion-requested/disputed，不含 open）、未读通知、已报名活动；点击分别进入“我的”/“消息”。计数仅当前浏览器合成数据。
- 首页安全说明打开时 `.home-main-content` 设置 `inert`，关闭恢复并把焦点归还“查看说明”；与 App 层说明弹层、A+ 弹层的 inert 行为一致。
- 旧存档迁移：载入时 `hidden` + accepted/completion-requested/disputed 的订单自动置为 `cancelled-local-demo` 并追加 `cancel/审核员`；事件已满 100 条时只改状态。迁移事件 ID 固定为 `EVT-LEGACY-CANCEL-<postId>`，重复载入不会再追加。
- 完成确认容错：只要求状态为 `completion-requested` 且当前角色为作者/接单成员，不再要求最后事件是对方的 request-completion；这覆盖只剩 accept 事件的旧单，也意味着状态是唯一事实来源。
- 深链：服务记录按钮携带帖子 ID，社区页清空筛选/搜索后滚动聚焦 `[data-post-id]` 并高亮 4 秒；深链不写 URL，刷新不保留。
- 举报容量：先查重再检查 200 条上限，重复举报在容量边界仍返回“已有待处理”。
- A+ 历史死锁投诉：详情优先提示“该历史投诉组合没有可用复核角色”；备份导入拒绝待复核且无可用复核角色的投诉，避免导入后永久卡住。
- 订单事件上限：`ORDER_EVENT_LIMIT=100` 成为共享常量；`PostCard` 在达到上限且订单仍处于 open/accepted/completion-requested/disputed 时隐藏全部订单操作按钮，显示“后续订单操作已停用”的说明；store 的写入兜底不变。
- A+ 历史死锁投诉已实测：注入 review→referral 待复核投诉后详情只显示“没有可用复核角色”，导入含该投诉的备份会被拒绝；不再出现“当前角色可复核”的矛盾文案。
- 审核内容筛选：`ModerationView` 增加三组筛选——内容（全部/待审/通过/下架/驳回）、举报（待处理/已处理/不予支持/全部）、订单留言（全部/未下架/已下架），均带计数和空态；筛选状态仅当前页面内存，不持久化。
- 评论管理：原“待审评论”扩展为全状态列表（待审/通过/驳回/下架/全部），待审可通过/驳回，已通过可下架，驳回/下架可恢复；空态与所属帖子标题、状态一并显示。仍是本机审核记录，不发送通知。
- 审核筛选偏好：四组筛选写入 `community-mvp.moderation-filters.v1`（与审核存档分离），加载时逐项校验并回退默认；页面提供“重置筛选”。localStorage 失败时静默回退，不影响审核写入。
- 审核搜索：一个输入框叠加过滤五类列表，字段覆盖标题/正文/ID/作者/地点/举报理由/目标预览/留言内容/线程标题/日志动作与结果；不区分大小写子串匹配，不写存档与审计日志，不持久化。审核日志另有动作筛选（5 种动作 + 全部），动作筛选随其他审核筛选写入本机偏好。
- 消息页筛选：系统通知“全部/未读”与“我的举报”四档处理状态筛选；通知未读数与已读游标保持一致，筛选本身不改写已读状态。筛选只存在页面内存。消息页另有搜索，叠加过滤通知/反馈/举报/订单留言（含未下架留言内容），不覆盖已下架留言。系统通知新增类型筛选（审核/订单/举报/留言/其他）；新通知带 `noticeKind`，旧通知按内容关键词归类。
- 举报结果通知：审核员把本机演示用户的举报标为已处理/不予支持时，写入一条系统通知，包含举报 ID、结果与理由；历史无举报人的举报不补发。该通知与其他系统通知一样参与未读计数和筛选。
- 订单体验记录：`Post.orderFeedback` 只允许出现在已完成求助单，1–5 星整数 + ≤240 字说明 + 时间 + synthetic；同一订单仅一次，仅发布者/接单成员可提交与查看摘要，不通知、不写审计、不影响真实信誉或结算；导出/写回保留该字段。服务记录新增“有体验”筛选并显示条数/平均星级/5–1 分布，聚合只统计本人参与的已完成订单。
- 审核工作台概览：四张实时计数卡（待审发布/待审评论/待处理举报/订单留言），点击滚动并聚焦对应区块，同时把评论/举报/留言筛选切回默认；只读统计，不写存档或审计日志。
- A+ 统计卡：待分诊/初筛中/逾期/高风险四张按钮卡点击即设置队列筛选，选中态 `aria-pressed`；新增“待分诊”“初筛中”筛选复用 `triageCases`/`screeningCases`，高风险停止单不落入这两类。筛选写入 `a-plus.intake-filter.v1`，刷新恢复，非法值回退“全部记录”。
- A+ 常规流程以分层门槛控制：演练同意确认后才可初筛、请求/恢复补充信息、接单、转介、跟进、模拟联系或记录已提供信息；仅接单、转介、跟进和模拟联系另要求必填信息完整。请求补充信息仍可用于补齐缺项；高风险交接和安全退出不受此门槛限制。
- 门槛提示在领域校验、存储层和界面共用，未确认同意与信息不完整会显示不同原因。检查点是本机合成流程字段，不代表真实法律同意、授权或运营准入。
- 浏览器两个入口处于同源时可读同一 localStorage；跨标签 `storage` 事件可用于提示刷新。
- 当前工作目录不是 Git 仓库；本轮不初始化仓库或执行 Git 操作。

## 需要保持的限制

- 本机读取只为同一浏览器的合成演练提供演示，不是跨设备同步，也不等于居民收到通知。
- 不把紧急求助升级成真实响应、呼叫或派单。
- 不向 DeepSeek 或其他协作服务发送真实居民数据、密钥或生产导出。

## DeepSeek 审查

- 已完成只读代码审查，未修改文件、未运行测试。发现居民侧进度缺失、社区已接单求助被 A+ 过滤、非求助坏数据可能阻断求助读取等问题；本轮已补齐居民侧只读进度，接纳已接单求助，并先跳过无关非求助内容再校验求助字段。
- 用户自己发布的求助仍不可自己接单，这是刻意保留的角色分离规则；求助方视角用预置他人求助可演练接单，或用“代合成邻居接单（演练）”按钮补齐发布者视角。后者是明确标注的合成代记录，不表示真实志愿者接单。
- 实名核验、真实通知、紧急调度、自动入单与履约不在本地合成原型范围内，实际运营前仍需另行设计和授权。
