# 方案 B：受控社区 MVP

依据：用户 2026-10-21 提供方案截图，并明确“按照方案B来做”。此前选择的 Vue 3 + Vite + Vant、本地合成数据原型继续适用。

## 体验路径

1. 打开 `/community.html`，默认是未核验访客。上方切换为本社区已核验合成成员后体验。
2. 发布求助、志愿活动或邻里分享，进入待审。到“我的发布”查看状态。
3. 切换为合成审核员，进入“审核”，填写理由后通过或驳回帖子/评论；所有操作记录日志。
4. 切回成员，审核通过且选择公开的帖子出现在首页、搜索和社区信息流。
5. 对开放的他人求助演练接单；接单后在求助卡片内走“发起完成申请 → 代合成求助方确认完成”，或由求助发布者走“代合成接单方申请完成 → 确认完成”。订单可取消/关闭，也可发起争议后撤销或关闭；每步写入订单事件时间线。完成会生成一条“未结算”演示时长，不能兑换或结算。
6. 活动招募可演练报名和取消报名；志愿记录等普通动态不提供报名（界面与共享 store 函数都校验）。审核结果和订单事件会出现在“消息 → 系统通知”，仅保存在本机。
7. 在帖子、评论或订单留言中填写举报理由，审核员查看目标内容后记录处理结果；需要下架时单独执行下架动作。
8. 下架内容退出信息流，对应订单停止留言；完成或关闭的订单留言只读。刷新后审核、举报、订单事件和留言仍从同一浏览器读取；演练身份不作为真实登录保存。“我的”可查看本机存档 JSON 只读快照，不提供导入或上传。

## 原型边界

- 所有数据均为虚构，只保存当前浏览器，不联系居民或任何机构。
- 身份切换是流程演示，浏览器数据可被本机用户修改；没有真实账号安全、实名核验或后台隔离。
- 双人履约流程中的“合成对方”按钮仅用于补齐演示；它记录一个明确标注的合成事件，不代表另一位真实居民参与、确认或收到通知。
- 留言只在本人参与、进行中且已审核通过的求助内产生；不承诺真实投递、回复或履约。完成/关闭后留言只读。
- 历史存档缺失审核字段时按待审处理，不自动公开；旧存档中已接单但没有订单事件时间线的求助会显示“无法还原历史步骤”，后续操作从当前状态继续记录。存档错误/冲突处理继续使用已有保护。
- 旧版自由聊天和未提交反馈可保留在原存档中，不再作为私聊入口显示。举报为新的本机演练流程。
- A+ 内部工作台继续保留，社区求助读取器只读取审核通过的求助（任何本机订单状态都只作展示）。

## 实际运营前待办

- 确认实际运营社区、主体和负责人；按实际主体、业务和地区确认备案及平台准入要求。截图中的主体建议不是已完成的法律合规结论。
- 确定邀请规则、社区成员核验方法、退出规则与审核员授权；最小化收集个人信息。
- 建立内容规则、审核值守、举报处理时限、申诉、紧急事项转交与审计制度。
- 服务端实现认证、角色权限、社区数据隔离、不可由客户端伪造的审核日志、数据库和备份、多端一致性、限流与内容处理。
- 在真实上线前另行完成部署、安全和运营验收。本原型不接收真实居民数据。
