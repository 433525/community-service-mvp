**下一轮先做 2 项**：

1. **Token 与可读性统一**（Vant 4 + Open Props，效率最高）：先把社区 7–11px 的正文/说明抬到 12–14px，输入控件 16px，正文对比度 ≥4.5:1；同步映射 `PostCard`、我的服务记录、A+ 社区读取面板、帮助弹层和移动端。
2. **弹窗焦点与播报收口**（a11y-dialog + APG + WCAG，风险最高）：给背景加 `inert`/`aria-hidden`，统一“打开进焦点、Tab 圈闭、Esc 关闭、关闭归还”，破坏性操作改用 `alertdialog`；同时把 toast/错误/保存状态收成 polite/assertive 两条播报通道。

## 1. 评审方法与评分表

### 1.1 独立评分口径

四项权重由任务指定，每项先打 0–100 的子分，再按权重合成：

| 维度 | 权重 | 判断问题 |
|---|---:|---|
| 关联度 | 40 | 是否直接命中本项目已有的页面/组件/约束，而不是泛泛的“前端最佳实践” |
| 效率收益 | 25 | 是否减少重复实现、减少决策时间，或让后续改动更可复用 |
| 审美/体验收益 | 20 | 是否改善层级、可读性、一致性、键盘/读屏体验，而非只增加“效果” |
| 集成成本与风险 | 15 | **分数越高越省事**：依赖、网络、构建、样式冲突、许可与维护风险越低 |

合成公式：

```text
总分 = 关联度 × 0.40 + 效率收益 × 0.25 + 审美/体验 × 0.20 + 集成成本与风险 × 0.15
```

**阈值与硬门槛**：总分 ≥70 才进入采纳/借鉴清单；同时必须通过以下门槛，否则即使分数高也不建议引入：

1. 许可可核实且允许当前用法；许可证不明、双许可冲突、或只能“整段搬运”的，不进入 adopt。
2. 与 Vue 3 / 现有 Vant 依赖兼容；React-only 不进入评分。
3. 离线可用；不依赖外部 CDN、外部字体、云服务、密钥或后端。
4. 不要求替换现有自研 UI 架构，不引入第二套完整移动组件库。
5. 维护状态可接受；最近发布/提交停滞超过 12 个月，或明显是无人验证的新仓库，不作为 adopt。
6. 能映射到具体页面/组件；只停留在“理念很好”的，归入 borrow-only 或暂缓。

### 1.2 与两份候选清单的关系

- 两份清单的“关联度”是侦察阶段的初筛分，本评审**没有直接沿用**；所有分数按上述四项重新计算。
- 合并重复项：`web-design-guidelines` 是 `web-interface-guidelines` 的本地壳，按一个候选评审；Vant、Open Props 在两份清单重复出现，也各按一个候选计算。
- 本评审纠正了两处事实口径：
  1. **Vue 官方文档不是 MIT**。公开 `vuejs/docs` 的 `LICENSE` 为 **CC BY 4.0**（图片除外），引用/改写需要署名并标注修改；本评审因此把它从“可直接复制的 MIT 文档”降为 borrow-only。
  2. **VueUse 不进入 ≥70 清单**。本项目的实际收益主要集中在 `useLiveAnnouncer` 一个点；`usePreferredReducedMotion` 与 `useScreenSafeArea` 的现有 CSS 已能覆盖大部分场景，为 1 个 composable 增加依赖不划算。可在未来需求累积后重评。

## 4. ≥70 清单：逐项判断与最多 3 步落地

> 统一约定：下面每一步都是**未来实施建议**，本轮不执行；文件路径相对 `a-plus-app/`。所有“引入文件”的建议都应同时保留上游 LICENSE 与来源链接。

### 4.1 Vant 4 — 82 — **adopt（仅 token 与结构，不换组件体系）**

**公开事实**：`vant@4.10.2` 的 npm 元数据声明 MIT，`peerDependencies.vue` 为 `^3.0.0`；项目已在 `package.json` 中以 `^4.10.2` 使用。它不是新依赖，不存在“再引一个 UI 框架”的问题。社区入口 `src/community/main.ts:4-11` 已手工引入 Vant 的 CSS 变量与基础/弹层样式；A+ 入口没有引入 Vant CSS。

**为什么是 82**：关联度高，因为社区入口已经有 `--van-*` CSS 变量在页面生效；效率高，因为可以直接借它的间距、字号、行高、圆角、时长阶梯，而不是自创一套；审美只给 64，因为 Vant 默认观感与现有 68KB 自研社区样式并不一致，必须“借 token，不套默认皮肤”。

**最多 3 步**：

1. 在两个入口的 `:root` 建立一层语义别名：`--space-1..6`、`--text-xs..lg`、`--leading-*`、`--radius-*`、`--duration-*`。社区入口可直接引用 `--van-*`，A+ 入口未引入 Vant CSS，只复制数值、不为了 token 给 A+ 引 Vant 基础样式；不覆盖 `--van-primary-color` 等运行时变量本身。
2. 用这层别名替换 `src/style.css` 与 `src/community/style.css` 中的裸数值，先处理 `src/community/components/PostCard.vue` 的标题/正文/操作行、`src/community/views/ProfileView.vue:273-305` 的服务记录与 `:320-326` 的时间账本、`src/App.vue:1495-1564` 的桥接面板。
3. 只在空状态借鉴 Vant `Empty` 的“图形 + 说明 + 一个明确动作”结构，内联 SVG 或纯 CSS 绘制，不引 `@vant/assets` 的外链图；发布表单暂不整体换 Vant Form，避免一次性改动字段校验与样式。

**风险/边界**：Vant 4 的无障碍是 “still improving”，不把它当合规保证；`--van-gray-6` 对白底只有约 2.92:1，不能用于小字；新增组件时必须同步补对应 CSS，否则样式缺失。

### 4.2 vercel-labs/web-interface-guidelines — 82 — **adopt（本地留档，不联网抓取）**

**公开事实**：仓库 `LICENSE` 为 MIT；规则本体是框架无关的 Markdown，官方 Skill 的工作流是联网抓取 `command.md`。本项目离线演示，必须把规则复制到本地后再用。

**为什么是 82**：它补齐的是“可机检项 + 反模式”这一层，和 frontend-design 的“审美判断”互补；关联度高，因为当前样式里已有 `transition`、焦点环、触控目标、移动安全区、表单 label 等可直接对照的点；成本低，因为不进入运行时。

**最多 3 步**：

1. 将上游 `command.md` 与 MIT LICENSE 复制到项目的 `docs/reference/web-interface-guidelines.md`（未来实施；本轮不创建），文件头写清来源、抓取日期、版本/commit。
2. 删掉不适用于中文界面的条目（如英文 Title Case、弯引号要求），把 React/Next 术语改写为 Vue 对应项：`@click`、`:focus-visible`、`<Teleport>`、`v-if` 卸载与焦点、`prefers-reduced-motion`。
3. 用它审 `src/App.vue`、`src/style.css`、`src/community/App.vue`、`src/community/style.css`，输出 `文件:行号` 清单；先修“会导致用户无法操作”的项，不为了满分改视觉语言。

**风险/边界**：规则偏 Web/React 语境，不能机械照搬；它查不出层级、品牌气质与中文文案问题；本地副本需要随上游更新手动同步。

### 4.3 Open Props — 79 — **borrow-only（只抄少量变量，不引包）**

**公开事实**：`open-props@1.7.23` 的 npm 元数据声明 MIT；提供 `sizes`、`easings`、`fonts` 等 CSS 自定义属性文件，可离线复制。它不是运行时库，也没有框架绑定。

**为什么是 79**：它精准补上“只有颜色 token、没有尺寸/字号/缓动阶梯”的缺口；纯 CSS，无构建要求；但全量 500+ props 会与 Vant 变量、现有品牌色打架，所以只值得借 10–15 个值，不值得引整包。

**最多 3 步**：

1. 在 `src/assets/tokens.css`（建议新增）只落 10–15 个变量：3–4 个 fluid size、3–4 个 font-size、2–3 个 easing/duration；文件头注明 `adapted from Open Props v1.7.23, MIT`。
2. 把 `src/community/components/PostCard.vue` 的卡片间距/正文行高、`src/community/views/ProfileView.vue` 的服务记录行距、`src/App.vue` 桥接面板的窄屏间距、两个帮助/安全弹层的 padding 改为引用这些变量。
3. 只在中性 spacing/缓动上使用；品牌绿、米白、陶土色仍由项目自己的 token 决定，不引入 Open Props 的通用色卡。

**风险/边界**：`--font-sans` 是拉丁优先，中文必须显式补 `PingFang SC`/`Microsoft YaHei`/`Noto Sans SC`；不要把 fluid 字号当作“把 10px 合理化”的工具，正文基础字号仍应 ≥14px，输入控件 ≥16px。

### 4.4 frontend-design — 77 — **adopt（评审流程，不重做视觉识别）**

**公开事实**：本地 `SKILL.md` 存在，公开路径的 `LICENSE.txt` 为 Apache-2.0。它是纯 Markdown 指南，不进入运行时。它的“反 AI 味”清单明确点名了：全大写小标签、`A · B · C` 中点串、按钮末尾加 `→`、统一圆角卡片 + 同一灰影、每节 fade-up 等；这些在现有社区页里确实能看到影子。

**为什么是 77**：审美/体验子分最高（82），能直接约束“越改越像模板”的风险；文案规则（CTA 说清后果、动作名全流程一致、错误说清原因与下一步）对帮助弹层、服务记录空态、A+ 桥接提示都有用。扣分在于它是方向性的，不给数值，且“设计工作室主创”的口吻容易诱导大改；本项目已经有明确的绿色/米白/手绘社区识别，不能借它推翻。

**最多 3 步**：

1. 把它固定为 UI 评审的第一道口，只取三组规则：反模板清单、文案一致性、质量地板（响应式、焦点、减弱动效）；不照搬“重新选字体/重新做 hero”的建议。
2. 用这三组规则审 `src/community/App.vue:211` 的 `HOW THIS DEMO WORKS` 眉标、`src/community/components/PostCard.vue:207-214` 的操作符号、`src/community/views/ProfileView.vue` 的空态与按钮、`src/App.vue` 桥接面板的说明句；只删“不承担信息”的装饰，不删品牌文案。
3. 统一 CTA 与结果文案：例如“登记到 A+ 队列”成功后仍用“已登记”，按钮/提示/空态使用同一动作名；错误提示补“发生了什么 + 怎么改”，不在错误里写“请重试”这种空话。

**风险/边界**：它是 Apache-2.0，若把大段原文复制进项目文档，需保留 LICENSE 与版权声明；仅作为内部评审清单不涉及再分发。不要用它把现有视觉识别改成另一套“高级感”。

### 4.5 Vue 官方 Accessibility 指南 — 77 — **borrow-only（按 CC BY 4.0 署名）**

**公开事实**：`vuejs/docs` 的 `LICENSE` 为 **CC BY 4.0**（图片除外），不是候选清单里写的 MIT。内容覆盖 skip link、landmark、标题层级、表单 `for/id`、`aria-*`、视觉隐藏文本、按钮 `type` 等，且是 Vue 官方语境。

**为什么是 77**：关联度高，尤其是“无 vue-router 的多视图切换也要把焦点送回主内容”这一点，正好补 `community/App.vue:navigateTab()` 这类只改 `activeTab` 的行为；但它是文档，不是代码，且需要署名/标注修改，所以只借清单，不整篇复制。

**最多 3 步**：

1. 写一份 6 条的本地检查项：skip link 落点、切视图后焦点到 `main`/`h1`、每页一个 `h1` 与正确 landmark、表单显式 label、图标按钮可访问名、装饰图形 `aria-hidden`；注明“改编自 Vue Accessibility 指南，CC BY 4.0”。
2. 先应用到 `src/App.vue:1160,1181` 与 `src/community/App.vue:129,170`，再检查 `ProfileView`/`PublishView`/`MessagesView` 的标题层级和表单。
3. 把“切视图回焦”做成一个小函数，在 `navigateTab()` 与 A+ 的视图切换处调用；不要在每个页面各写一遍。

**风险/边界**：指南部分链接仍指向 WCAG 2.1，条款编号需对到 2.2；示例里的 FontAwesome 等外部图标不适用于本项目；它不覆盖 `<Teleport>` 弹层的焦点圈闭，需配合 APG/a11y-dialog。

### 4.6 WCAG 2.2（A/AA）— 76 — **borrow-only（只取可验证口径）**

**公开事实**：W3C 页面提供 WCAG 2.2 概览、At a Glance、Quick Reference；W3C 页面声明 permissive license / WAI 材料使用条款。它是标准，不是组件库；本评审只引用，不复制全文。

**为什么是 76**：它是所有清单的最终对账口径，能防止“看起来更好但不可用”；但条款抽象、英文、篇幅大，直接转成代码的效率不高，所以只借 A/AA 中与本项目有关的少数硬指标。

**最多 3 步**：

1. 只取 6 条做本轮门槛：正文对比度 ≥4.5:1（大字 ≥3:1）、焦点可见、触控目标 ≥44×44、键盘可完成主流程、错误不只靠颜色、`prefers-reduced-motion` 下内容仍完整。
2. 把这些门槛写进 token 注释与评审表，先测 `PostCard` 正文/日期、`ProfileView` 服务记录、`src/App.vue` 桥接状态、帮助弹层；不追求全站一次性达标。
3. 记录例外与未测项（读屏、真机、200% 缩放等），不写“已通过 WCAG AA”这类结论。

**风险/边界**：这不是合规认证；W3C 文档的再分发/翻译需遵循其条款；颜色计算未计透明度叠加、渐变与实际渲染，最终仍需浏览器/真机复核。

### 4.7 a11y-dialog — 75 — **borrow-only（不引 vanilla 库）**

**公开事实**：`a11y-dialog@8.1.5` 的 npm 元数据声明 MIT，技术栈为原生 TypeScript、无样式，依赖 `focusable-selectors`。它实现 WAI-ARIA APG 的 Dialog (Modal) 模式，支持 `alertdialog`、嵌套 dialog、背景隔离与焦点归还。

**为什么是 75**：本项目有 11 处弹窗，A+ 的手写逻辑已覆盖“首焦点/Tab 循环/Esc/归还”，但还没看到背景 `inert`/`aria-hidden`，破坏性确认也没有 `alertdialog` 语义；借它的行为清单比引入一个 vanilla 库再包 Vue 更划算。审美/体验子分低，是因为它不解决视觉。

**最多 3 步**：

1. 在打开弹层时给**弹层之外的背景容器**加 `inert`，关闭时恢复：A+ 可分别对 `.side-rail`、`.topbar`、`#aplus-main` 设置，或将弹层 Teleport 到应用根外后对根容器设置；社区对 `.topbar`、`.app-frame`、`.mobile-nav` 设置。绝不能把弹层自身也置为 `inert`；不支持 `inert` 的旧 WebView 用 `aria-hidden` + 焦点兜底。
2. 把“重置/覆盖存档”这类不可逆确认从普通 dialog 改成 `role="alertdialog"`，默认焦点放“取消”，并保留明确的“覆盖/恢复”后果说明；先改 `src/community/views/ProfileView.vue:185-193` 与 A+ 的恢复入口。
3. 用它的焦点过滤思路补现有 `dialogFocusables()`：排除 `disabled`、`hidden`、零布局、`visibility:hidden`；处理 Shift+Tab 与“焦点跑到弹窗外”的兜底；先只改 A+ 的一个弹窗做对照，再铺到其余。

**风险/边界**：`inert` 的浏览器支持需按目标设备确认；Vant 的 `showConfirmDialog` 与自研弹窗不能同时负责焦点，必须指定唯一所有者；不要为了“语义完整”给所有 `div` 加 role。

### 4.8 W3C ARIA APG — 73 — **borrow-only**

**公开事实**：W3C WAI-ARIA Authoring Practices Guide 的 Dialog (Modal) 与 Tabs 模式公开可读；W3C 页面声明 permissive license / WAI 材料使用条款。它提供键盘交互、角色/状态/属性与示例，不是 Vue 组件。

**为什么是 73**：它能把 `ProfileView` 的 tab 语义和帮助弹层的键盘行为对齐到行业契约；但项目多数交互可以用原生按钮/Vant 完成，过度 ARIA 反而增加风险，且需要手写 Vue，效率一般。

**最多 3 步**：

1. 只取两个模式：Dialog 的“焦点进入、Tab 圈闭、Esc、归还、背景 inert”；Tabs 的“左右方向键、Home/End、`aria-controls`/`tabpanel`、`aria-selected` 同步”。
2. 先修 `ProfileView.vue:252-254` 的 5 个 tab：加 `id`/`aria-controls`、 `role=tabpanel` 与 `aria-labelledby`，实现左右键与 Home/End；保持点击仍可用。
3. 用帮助弹层做一次键盘走查：打开后焦点落在标题或关闭按钮，Tab 不跑出弹层，Esc 关闭，关闭后回到“说明”按钮；不重写已经通过的社区弹层。

**风险/边界**：APG 示例不是 Vue 实现；不要给普通按钮强行加 `role=tab` 却没有对应 panel；读屏器实际播报仍需人工测试。
