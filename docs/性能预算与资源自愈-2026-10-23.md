## 2. 调研与取舍

| 来源 | 可借鉴要点 | 本次处理 |
| --- | --- | --- |
| [Vite · Build · Load Error Handling](https://vite.dev/guide/build.html#load-error-handling) | 动态导入失败会派发 `vite:preloadError`，`event.payload` 是原始错误；`preventDefault()` 可阻止抛出；发版删旧分块是典型诱因；HTML 必须 `Cache-Control: no-cache` | 采用事件 + `preventDefault`；冷却策略自加；HTML 缓存策略与 `docs/部署说明-2026-10-22.md` 第 4 节一致（`no-cache, must-revalidate`） |
| [ai/size-limit](https://github.com/ai/size-limit) | 按“传输体积”而非源码体积设限；默认 Brotli；初始上限建议在实测上加余量；超限让 CI 失败 | 采用其口径（minified + 压缩）；因为要跟 Vite 构建日志对得上，硬指标用 **gzip**，Brotli 只报告；余量取 10%（比其建议的 25% 更紧，项目已成熟） |

| [GoogleChrome/web-vitals](https://github.com/GoogleChrome/web-vitals) | CLS good ≤ 0.1、LCP good ≤ 2500ms；CLS 需常驻监听，隐藏时仍要回调 | 采用阈值；采集器常驻，读值时再算 |
| [web.dev · CLS](https://web.dev/articles/cls) | 会话窗口：最长 5s，间隔 > 1s 或超窗则另开；忽略 `hadRecentInput` 的偏移 | 完全按此实现，并抽到 `tools/lib/web-vitals.mjs` 供单测复用 |
| [Vite · Browser Compatibility](https://vite.dev/guide/build.html#browser-compatibility) | 默认目标为 Baseline Widely Available：Chrome/Edge ≥ 111、Firefox ≥ 114、Safari ≥ 16.4 | 作为兼容基线写进本文；项目用到的 `inert`（Safari 15.5+）、`env(safe-area-inset-*)`、`backdrop-filter` 均在该范围内 |

**分歧处理（以官方文档为准）**：

1. **`event.payload` 还是 `event.detail.payload`**：社区文章与旧版本文档多写后者。当前 Vite 官方文档写的是 `event.payload`；实现同时读取两者，主路径按文档，兼容旧写法。
2. **超限是否阻断**：size-limit 的 README 只说“抛错让 CI 失败”，未写退出码。本实现显式 `exitCode = 1`，并保留 `--report` 采集模式。
3. **预算余量**：size-limit 建议 +25%，但那面向“刚接入、依赖还在长”的库。本项目体积已稳定，取 +10% 才能拦住渐进膨胀。

## 3. 实现

### 3.1 资源载入失败自愈

```
用户点击「消息」页签
  └─ 动态 import（首次进入才加载 MessagesView 分块）
       ├─ 成功 → 渲染
       └─ 失败（弱网 / 发版后旧分块已删）
            ├─ Vite 派发 vite:preloadError
            │    ├─ 60s 内没刷新过 → 记录时间 → preventDefault → 整页刷新（拿新 HTML 指针）
            │    └─ 冷却期内 → 不阻止，交给下一步
            └─ loadWithRetry：400ms 后重试 1 次
                 ├─ 成功 → 正常渲染
                 └─ 仍失败 → ViewError「页面载入失败」+ 重新载入
```

设计取舍：

- **整页刷新而不是局部重试**：分块 404 说明 HTML 指针已过期，只有重新取 HTML 才能拿到新文件名。
- **冷却用 sessionStorage**：同一标签页内防死循环；隐私模式下写入失败时退化为模块内存标记，不抛错。
- **不做自动重试 N 次**：一次重试足以覆盖瞬断；更多次数会在真 404 时拖慢错误提示。
- **`preventDefault` 只在确实要刷新时调用**：冷却期内保留默认行为，让 asyncView 的错误组件拿到拒绝，用户能看到可操作提示。

### 3.2 无脚本兜底

- 两个入口的 `<noscript>` 用内联样式（不依赖 CSS 产物），说明「需要启用 JavaScript / 可用浏览器 / 只含合成数据 / 如何进入另一入口」，并给出 44px 高的「启用后重新载入」链接。
- 加 `<meta name="format-detection" content="telephone=no">`：合成演练文本里出现数字串时，iOS Safari 不应把它变成拨号链接。
- 兜底页没有引入新的网络请求，不破坏 `check-deployability` 的“零外链”约束。
- 专项门禁 `check-noscript.mjs` 用 `Emulation.setScriptExecutionDisabled` 真禁用页面脚本，再读 DOM 与盒模型：**20/20**。证据图在 `docs/运营准备/evidence-noscript/`。
- 顺带修正一处闸门误报：兜底页会链接回 `/`，而 `check-deployability` 原来把 `/` 当文件查，必然报断链。现按静态托管语义把目录型路径归一化为 `index.html`（这是修误报，不是放宽标准）；归一化后仍是 **6/6**。

### 3.3 首屏载荷预算

统计口径（与“首屏真正要下载的东西”一致）：

```
入口首屏 JS = <script type="module" src> + 该页全部 <link rel="modulepreload">
入口首屏 CSS = 该页 <link rel="stylesheet">
```

实测与上限（1 kB = 1024 B）：

| 入口 | 首屏 JS（raw / gzip） | 首屏 CSS（raw / gzip） |
| --- | --- | --- |
| A+ 受理工作台 | 254.3 kB / 79.8 kB | 32.4 kB / 7.4 kB |
| B 社区端 | 190.5 kB / 66.1 kB | 71.9 kB / 14.4 kB |
| 全站合计 | 424.7 kB / 134.9 kB | 105.5 kB / 22.3 kB |

上限取值：入口级与单资源级 = 实测 + 约 10%；全站总量再留一点跨入口重叠的余量。逐项数值见 `tools/budget.json`，每次运行的完整报告落在 `docs/运营准备/evidence-budget/budget-report.json`。

**为什么 A+ 的 JS 比 B 大**：A+ 把 11 个版面 + 10 个弹层编译进同一个入口（128 kB），并把 `intake-progress`（39.6 kB）作为启动即用的共享模块预加载。B 端除首页/社区外的四个页签已按需分块，所以入口更小、CSS 更大（14 个分层样式文件无法按页签拆分）。

### 3.4 运行时 Web Vitals

- 采集器通过 `Page.addScriptToEvaluateOnNewDocument` 注入，在文档开始前注册 `layout-shift` / `largest-contentful-paint` / `longtask` / `paint` 四类观察器，保证首屏偏移不被漏采。
- CLS 用会话窗口合并（`tools/lib/web-vitals.mjs` 的 `clsFromShifts`），同一份函数既注入浏览器也跑单测。
- 覆盖 6 个状态：B 首页（1440/390，清空存档的首次访问）、B 社区动态（深链首渲染）、B 发布页（按需分块路径）、A+ 队列（1440/390）。
- 阈值：CLS ≤ 0.1、LCP ≤ 2500ms（web-vitals good 档）、最长任务 ≤ 200ms、TBT ≤ 300ms。本机实测 LCP 32–64ms、CLS 0、长任务 0，阈值留出的是回归余量，不是“刚好通过”。
- **采集器自检**：脚本最后会人为插入一个 0 → 180px 的占位元素制造布局偏移，确认 `shiftCount` 从 0 变 1。没有这一步，“指标全是 0”既可能是真的好，也可能是观察器没生效。

### 3.5 视觉基线扩容（顺手收口）

原来只覆盖 8 个状态，弹层与审核页完全没有像素保护。本轮补 3 个：

做法与风险控制：

- 先备份原 8 张基线，再跑 `--update`；逐张比对哈希，确认原状态**一个像素都没变**（结果是 8 张全部 SAME）。
- 新状态连续跑两次比对，均 **11/11**，确认弹层焦点态与 screenshot 时机是确定性的。

## 5. 维护手册

**什么时候会触发载荷门禁？**

- 新增依赖、把按需加载改成静态导入、复制大段样式；
- 新增入口页（记得同时在 `tools/budget.json` 里加条目，否则门禁会报“配置缺失”）；
- 升级 Vue / Vite 导致运行时变大。

**超限了怎么办？**

1. 看报告里哪一项超：入口级、单资源级还是全站总量；
2. 用 `--report` 重跑拿完整 JSON，对比上一次的 `entries[].chunks`；
3. 优先找可回收空间（按需加载、去重、删无用样式）；确认无空间后再上调上限，并在本文补一行说明。

**为什么不直接接 Lighthouse / size-limit？**

- 离线环境，禁止 `npm install`；
- 需要的是“同机同浏览器、可重复”的回归，而不是一次性评分；
- 现有 `tools/cdp.mjs` 已经能起浏览器、注入脚本、读值，复用它比引依赖更可控。
