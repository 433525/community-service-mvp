## 2. GitHub 参考研究（按开发步骤）

> 规则：先查同类优秀开源项目，提炼可借鉴点，再在现有文件上实现；**开源代码与官方文档冲突时以文档为准**。本轮只借鉴模式与数值，不复制代码，不新增运行时依赖。

### 2.1 设计令牌与字号基线 → [`primer/primitives`](https://github.com/primer/primitives)（GitHub，MIT）

- **读到的做法**：令牌分 Base（原始值）与 Functional（语义别名）两层；间距统一 6 档（2/4/8/12/16/24）；动效 4 档时长；改名时保留 deprecated alias 过渡。
- **落到本项目**：两套入口都建立 `--fs-*`、`--sp-*`、`--r-*`、`--shadow-*`、`--ease/--dur` 两层令牌；保留 `--text-body/--text-title/--tap-min` 兼容别名指向新阶梯，避免一次性替换造成回归；间距收敛为 4/8/12/16/20/24/32。
- **未采纳**：不引入 `@primer/primitives` 包（离线约束），不复制其主题文件。

### 2.2 可访问组件与错误处理 → [`alphagov/govuk-frontend`](https://github.com/alphagov/govuk-frontend)（MIT）+ [GOV.UK 错误摘要文档](https://design-system.service.gov.uk/components/error-summary/)

- **读到的做法**：组件以 WCAG 2.2 AA 为交付门槛；**错误摘要放在 main 顶部、提交后把焦点移到摘要、每条错误链接到对应字段，且摘要与字段旁文案完全一致**；标题层级与表单标签强绑定。
- **落到本项目**：
  - 所有弹层校验错误已用 `role=alert` + 字段 `aria-describedby`（原有能力保留）；
  - 本轮补：弹层 `aria-describedby` 指向头部说明、初始焦点优先落在首个可编辑字段（而非关闭按钮）、结果数量 `role=status aria-live=polite`；
  - 触控基线取 **44×44**（WCAG 2.2 SC 2.5.8 要求 ≥24，44 是本项目更严格的自定基线）。
- **文档优先的实例**：GOV.UK 文档要求「错误摘要必须获得焦点」，而本项目是局部弹层表单、无整页跳转；据此实现为「弹层打开即聚焦首个字段 + 错误区 `role=alert` 即时播报」，而不是照搬整页摘要。

### 2.3 社区信息流与审核 → [`discourse/discourse`](https://github.com/discourse/discourse)（GPL-2.0，只读参考）

- **读到的做法**：统一 `reviewable` 审核实体与审核队列；通知按类型建模并区分已读；信息流卡片按「谁 + 什么 + 多热」分层；序列化按视图裁剪字段；对外举报有案号与回执。
- **落到本项目**：
  - 审核页保留四张实时计数卡 + 四组筛选 + 跨类搜索（原有）；
  - 本轮补：审核页顶部统一结果播报（内容/评论/举报/留言计数），消息页把「系统通知」前置到首屏并按类型筛选；
  - 卡片信息分层：类型/时间 → 作者/地点 → 标题 → 正文 → 结构化标签 → 操作，正文不再与元信息同字号。
- **未采纳**：不引入信任等级、自动隐藏阈值、插件机制（无后端，且会改变既有验收契约）。

### 2.4 表单、焦点与弹层 → 项目既有评审（本地文档，非外部代码）（`docs/开源与Skill采纳评审-2026-10-21.md`）

- 采纳其中已论证的结论：Vant 只借 token 不套皮肤；`a11y-dialog` 的焦点闭环模式；ARIA APG 的 Tabs 键盘契约；Open Props 只抄变量。
- **本轮反向决策**：Vant 仅剩 `showConfirmDialog` 一处用途，却带来约 16KB CSS 与一套异构弹层。按「不引第二套 UI 框架」的既有禁令，改为自研 `ConfirmDialog.vue`（焦点闭环、Esc、遮罩关闭、滚动锁），并移除 Vant 依赖与样式导入。

### 2.5 明确未做的事

- 未引入任何新依赖、外部字体、CDN、动画库；
- 未复制 GPL 代码；
- 未把社区产品的「信任等级/自动处罚」搬进演示原型（会与合成数据边界冲突）。

## 6. 已知风险与边界

1. **仅 headless Chrome 验证**：未覆盖 Safari/Firefox、真机、NVDA/VoiceOver/TalkBack、200% 缩放。320/390/720/1024/1440 宽度回流已在 headless Chrome 实测通过；`inert`、`backdrop-filter` 在旧浏览器可能降级，已保留不透明背景与焦点闭环兜底。
2. **对比度审计是计算样式推断**：半透明叠层与渐变背景可能存在 ±0.1 误差；英雄区白字已人工核对（深绿底）。
3. **桌面端紧凑按钮 30–38px**：符合 WCAG 2.2 SC 2.5.8（≥24），但未达 44；触控场景只在 ≤720px 生效。
4. **消息页仍较长**：通知、订单留言、反馈、举报四段并列，已有吸顶分区导航可直接跳转；若后续要求「消息即工作台」，需新增页签而不能继续堆叠（会引入隐藏内容，影响现有测试契约）。
5. **A+ 窄桌面（1021–1240px 且内容超高）**：队列面板内部滚动时，面板头与筛选条会随内容滚出；若需要常驻，可再加一层 `position: sticky` 到 `.panel-head`/`.filters`。
6. **旧脚本 `audit-a11y.mjs` 已过期**：其标题断言仍要求固定的「邻里 · 社区服务演练版」，页签标题上线后会失败；它不是门禁，保留追溯，不据此判断回归。
7. **未实际托管**：产物使用 7 个根路径绝对引用，只适配域名根路径；子路径部署会断链。真实 404 状态码需在目标托管平台验证（本机 preview 对未知路径会回退应用外壳）。
5. **无后端/真实数据边界不变**：仍是本机合成演练，不发送通知、不结算、不接真实居民数据。
6. **Vant 依赖已从 `package.json` 移除**，但 `node_modules` 未清理（离线约束，不执行 `npm install`）；不影响构建。
