# 2026-10-21 消息页通知与举报筛选实测

本轮为消息页补上通知/举报筛选，并让举报处理结果回到举报人的系统通知；同时验证通知未读/全部筛选。

- 构建：`npm run build` 通过（331 modules），dist 构建 2026-10-21 21:59:23
- 站点：`npm run preview -- --host 127.0.0.1 --port 5180 --strictPort`
- 浏览器：headless Chrome + `tools/cdp.mjs`；脚本 `tools/check-messages.mjs`
- 结果：**8/8 通过，失败 0**；页面未捕获异常 0

## 1. 本轮改动

- 系统通知标题旁新增“全部/未读”筛选，带计数；未读数量与“全部标为已读”按钮保持同步。
- “我的举报”新增“全部/待处理/已处理/不予支持”筛选，带计数。
- 两组筛选均为页面内存状态，不持久化、不写存档；未读游标仍只由“全部标为已读”更新。
- 空态按筛选显示：“当前筛选下没有通知”“当前筛选下没有举报记录”。
- 举报处理闭环：审核员记录“已处理/不予支持”时，若举报人为本机演示用户，追加一条系统通知，包含举报 ID、结果和理由；旧存档无举报人的举报不补发通知。
- 消息页新增搜索框，叠加过滤系统通知、反馈与“我的举报”；不改变订单留言、存档或已读状态。
- 系统通知新增类型筛选：审核/订单/举报/留言/其他（带计数）。新通知写入 `noticeKind`；旧通知没有该字段时按内容关键词归类（举报→留言→审核/下架→订单→其他）。
