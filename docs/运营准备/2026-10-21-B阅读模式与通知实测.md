## 2. 本轮实现内容

1. **大字/舒适阅读模式**：顶栏“字”开关（`aria-pressed`），在 `.community-app` 上加 `reading-large`，放大正文、标题、按钮、表单与底部导航字号，触控目标同步放大；偏好写入 `community-mvp.reading-mode.v1`，刷新后保留；与社区存档分离，不影响 A+。移动端仅显示“字”图标但保留 `aria-label`，键盘焦点环沿用深绿 `#2a6049`。
2. **系统通知未读状态**：`CommunityState.notificationsReadAt`（可选，旧存档兼容；旧存档载入时以最后一条历史通知为已读游标，不把历史当未读）。页面按未读数显示顶栏/侧栏/移动底栏角标，`document.title` 带 `(N)` 前缀；消息页显示“N 条未读”、逐条未读标记与“全部标为已读”。通知只在本机生成与保存。
3. **举报完整性**：`Report.reporter`（可选，旧存档显示“历史举报人未记录”，不推测补写）；同一举报人对同一目标存在待处理举报时不再重复创建；创建举报写入审核日志（新增动作 `create-report`，审核页显示中文动作名）；审核页与“我的举报”展示举报人。
4. **发布草稿自动保存**：发布表单内容与选项在停止输入约 400ms 后写入 `community-mvp.publish-draft.v1`；离开发布页/刷新后可恢复并提示；**不恢复**“虚构内容确认”勾选，提交前必须重新确认；发布成功或手动“清除草稿”后删除。草稿与其他存档分离、不上传。

## 4. 关键观察

- 未读游标与存档同写：一次写入失败时整次操作不应用；旧存档没有该字段时不会把所有历史通知标成未读。
- 草稿与“虚构内容确认”分离：确认框不会被草稿恢复，提交仍必须人为勾选，避免“草稿绕过合成数据确认”。
- 举报人、去重与 `create-report` 审核日志让举报从“孤立记录”变为可追溯的本机操作；旧举报记录显示“历史举报人未记录”，不会被猜测补写。
- 大字模式为纯本机 UI 偏好：不写入社区存档、不上传；关闭后删除偏好键。

## 5. 未覆盖项与限制

1. 移动端为 CDP Emulation（390×844），不是真机；未验证 iOS Safari 聚焦缩放、真实手势与安全区。
2. 未做读屏器（NVDA/VoiceOver）与全页键盘遍历；未做对比度仪器测量。
3. 未测多标签页冲突、存档容量上限、localStorage 写入失败路径（既有专项脚本覆盖部分存储异常，本轮未重跑）。
4. 大字模式只验证字号放大后的可用性与无溢出，未做真实用户阅读偏好测试；部分装饰性小字（如页脚 caption）未放大。
5. 未覆盖审核员下架/举报处理全链路与 A+“登记到 A+ 队列”动作（既有报告已列，本轮未重测）。
6. 未做性能、并发或跨设备同步测试；仍无服务端，所有数据仅当前浏览器。
