## 3. 分页面观察（视觉 / 层级 / 文案 / 移动端）

### 3.1 全局：B 每页先交"身份 + 免责"，再交内容

**实测（390）**：顶栏 64 + 页标题 40 + 免责条 51 + 身份卡 270 = **425px**，占 844 的 **50%**，之后才是页面自己的内容。社区、消息、我的、审核四页的首个任务内容 top 分别是 781 / 1033 / 494 / 1099。
**实测（1440）**：身份卡 145px，加上标题 47 + 免责 40，内容从 402 开始；首页到 473 才出现 hero。
**根因（代码推断）**：`src/community/App.vue` 181–194 把 `.page-heading`、`.prototype-banner`、`.membership-panel` 固定在每个 tab 的 `<main>` 顶部；身份卡同时承担身份切换、说明与安全声明三件事。
**截图**：[b-390-02-community.png](evidence-handoff-design/b-390-02-community.png)（首屏 0 帖子）、[b-390-03-messages.png](evidence-handoff-design/b-390-03-messages.png)（首屏 0 通知）、[b-1440-01-home.png](evidence-handoff-design/b-1440-01-home.png)。

### 3.2 全局：B 的页面标题是导航名，标题层数过多

**实测**：`h1` 分别为「首页 / 社区 / 消息 / 我的 / 审核」，上方还有 `.eyebrow`「社区服务 · 首页」；首页又有 `.welcome-row h2`「你好，演练居民」和 hero `h2` 42px「让互助就在邻里之间。」；社区有 intro `h2`「把日常分享出来…」。
**问题**：一屏内 3–4 个"标题级"文本，且最大的字是营销口号，不是任务；`h1=首页` 对用户没有任何信息量。
**截图**：[b-1440-01-home.png](evidence-handoff-design/b-1440-01-home.png)、[b-1440-02-community.png](evidence-handoff-design/b-1440-02-community.png)。

### 3.9 A+ 工作台：首屏是"控制面板"，队列在第一屏外

**实测（390）**：标题/操作 97–279；登记开关 279–439（160px，两段说明）；黄条 459–641（182px，含 4 个备份按钮）；统计卡 661–867；首个队列项 **982**。

**A+ 顶栏（390，实测）**：sticky 高 **97px**（因 flex-wrap 成两行），背景 `rgba(255,255,255,.72)`；滚动时下方按钮/文字会透出来（截图 `aplus-390-03-metrics.png` 顶部可见「导出备份」等重影），且没有品牌/标题，只有 10px 面包屑。
**统计卡装饰环（实测）**：`.metric-card::after` 是 78×78、`right:-17px; bottom:-27px` 的 13px 圆环；`.metric-foot` 的矩形（390 下 top 729–741、left 27–right 178）完整落在环的覆盖区内（环从 `card.right-61=130` 开始），第三、四张卡的「…点击筛选」被环遮住（`aplus-390-03-metrics.png`、`aplus-1440-03-metrics.png`）。

## 6. 5 条建议的排序理由

1. **先解决"看不见"**：V1/V2/V3 让首次进入者看不到帖子/通知/队列/待办，这是任何视觉打磨之前的前提；成本中等但收益最大。
2. **再解决"看不清/点不准"**：字号与 tap 基线是横切问题，越晚做，后续每条改动都要重新适配；已有 token 与文档欠账，边际成本最低。
3. **再解决"做不完"**：A+ 详情动作区是操作员最高频路径；S 成本、低风险，适合作为第一条落地项。
4. **再解决"找不到"**：消息/审核的页内 IA 与身份切换，是流程型页面的结构性缺陷。
5. **最后做"说不清"**：标题/文案/枚举清理，成本最低但依赖前面确定布局，避免白改。
