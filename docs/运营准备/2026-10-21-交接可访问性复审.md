### P2-2　`role="tab"` 语义不完整：无 `tabpanel` / `aria-controls`，无方向键漫游

**复现**：A+ `.filters[role="tablist"]` 两组（记录 7 格、投诉 2 格）；B 消息页 3 组、审核页 5 组。聚焦任一 tab 后按 →。

## 6. 优先修复建议（≤5 条）

1. **统一两套主题的「弱化文字」色阶（P1-1 / P1-2）**：把 8–11px 元信息的 `#94a0a2`/`#9eaa9f`/`#9aa49b`/`#838d84` 等统一提到 `#5f6f72` 级别（对白底 ≈4.6:1），并给 `.mobile-nav span`、`.profile-tabs span`、`.thread-item small`、`.banner-mark`、`.empty-state` 单独兜底；**先修 2.15–2.71 这 8 个组合**，成本低、收益最大。
2. **移动端筛选片与紧凑按钮补到 44px（P1-3）**：`.filters .filter`、`.compact-filter button` 高度 26→44（或加透明外扩命中区 `padding-block` / `::before`），`.moderation-actions .button-ghost` 最小宽度 33→44；弹层输入框 41→44。改动集中在两条 CSS，回归风险低（需重跑 390 截图）。
3. **B 搜索框恢复明确的焦点环（P2-1）**：去掉 `.moderation-search input { outline: 0 }` 或改为 `:focus-visible { outline: 2px solid #2a6049 }`，与 A+ 的 3px 环对齐；顺手把 `focus-within` 阴影提升到 3:1。
4. **给「结果计数」加播报（P2-3 / M1）**：三个结果区各加一个 `role="status" aria-live="polite"` 的计数节点（如「筛选结果 3 条」），随筛选更新；空态文案同时放入该节点。改动小、可测（现有脚本可断言文本变化）。
5. **把筛选组从 `role=tab` 改为 `role=group` + `aria-pressed`（P2-2 / M2）**：这些控件本质是单选筛选而非 tab 面板，改成 `role="group"` + 按钮 `aria-pressed` 后语义立即自洽，也免去补 `tabpanel`/方向键的成本；若坚持 tab 模式，则必须补 `aria-controls` + roving tabindex + ←/→。

## 8. 边界与声明

- **仅 headless Chrome 156（`--headless=new`）**，Windows 桌面渲染。**未做 NVDA / VoiceOver / TalkBack、未做真机（iOS/Android）、未做 200% 缩放、未做强制颜色模式/暗色模式/减少动画、未做表单自动填充与浏览器翻译场景**。因此「读屏实际朗读顺序与措辞」不在本轮结论内——本报告中所有 ARIA 结论均为 **DOM 属性 + 可访问名称可解析性 + 键盘行为** 的推断，不是读屏器实测。
- 对比度为**计算样式推断**（含 alpha 合成与祖先背景遍历）；背景含渐变/图片时跳过（两套应用本轮未命中跳过项）。字体渲染差异、抗锯齿、显示器色彩管理不在计算范围内。
- 触控目标按 `getBoundingClientRect()` 计算；复选框以包裹 `<label>` 为有效区域（点击 label 与点击控件等效）。
- 遮挡判定分两步：滚动位置命中测试（会命中「滚动经过固定栏」的瞬时重叠，不作缺陷）与**逐元素 `scrollIntoView(center)` 后的命中测试**（用于判定是否真的无法点击）。A+ 47 个、B 首页 35 个交互元素均 0 不可达；固定底栏在 4 个页面（A+ 与 B 消息/审核/服务记录）滚到底时被压正文文字均为 0。
- 数据全部为本机合成 fixture + 脚本生成的合成记录；未填写真实个人信息；未修改源码/文档/测试脚本；未执行 Git、安装、克隆、部署或外部 CDN；未终止主控 5180 进程（本次未另起服务，直接复用 5180）。
- 本轮**未复测**：审核筛选与 A+ 筛选的持久化（已由 `check-moderation.mjs` / `check-aplus-metrics.mjs` 覆盖）、通知已读游标细节、以及所有业务正确性断言——本报告只对「可访问性与移动端」负责。
