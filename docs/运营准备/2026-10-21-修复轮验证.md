## 2. 修复：A+ 读取器不再被单条损坏记录整份阻断

**问题（实测）**：向社区存档注入一条审核通过、但缺少 `orderStatus` 的求助后，A+「社区求助（本机演练）」读取结果是“社区演练存档读取失败”，**一条坏数据导致所有有效合成求助都无法登记**。原逻辑在 `src/domain/community-bridge.ts` 的逐条解析中遇到错误立即 `return { status: 'error' }`。

**修复**：
- `readCommunityHelpPosts` 改为**部分读取**：逐条解析失败的审核通过/待处理记录改为跳过并累积 `warnings`；重复帖子 ID 也跳过并警告；只有存档级问题（非 JSON、版本/结构不兼容、超上限）才整份失败。
- `ready` 结果新增 `warnings: string[]`；A+ 面板顶部状态显示“已读取 N 条合成求助；跳过 M 条无法解析的记录”，并展示前 5 条警告、提示原文未被修改；有效求助仍可正常登记。
- 不写回、不修复、不删除社区存档；坏记录不会出现在登记列表。

**修复后实测**：注入同一条坏记录后，状态为“已读取 3 条合成求助 … 跳过 1 条无法解析的记录”，3 条有效求助正常列出且可登记，警告区显示“社区演练存档第 7 条求助的登记状态无效”，无整份失败。截图 `evidence-fixes/fix-8-malformed-probe.png`。

涉及文件：`a-plus-app/src/domain/community-bridge.ts`、`a-plus-app/src/App.vue`（状态与警告展示）。A+ 其余流程与社区 store 未改动。

## 4. 关键结论

- 社区存档（含新增 `orderEvents`、`reporter`、`notificationsReadAt`）可通过自身导出 JSON 写回并重新载入，不触发 recovery；旧存档缺少新字段仍可读，未读游标按历史最后一条通知补齐。
- A+ 登记是单向写入：生成 `sourcePostId`/`community-entry-local` 记录，社区 `savedAt` 不变；重复复核分支会写 `duplicate-review` 事件并关联候选。
- 读取器的容错边界明确：存档级损坏仍整份失败并保留原文；单条记录损坏跳过并显式警告，避免“一条坏数据阻断全部登记”。

## 5. 未覆盖项

1. 本轮只修复读取器容错；社区页面自身遇到损坏存档仍进入 recovery-required（这是有意的原文保护），未做自动修复。
2. 真机、读屏器、对比度仪器未做；移动端只在其他轮用 CDP Emulation 验证。
3. 多标签冲突、存档容量上限、localStorage 写入失败注入未在本轮重跑。
4. 未执行任何 Git 命令，未同步私有仓库。
