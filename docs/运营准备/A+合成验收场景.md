# A+ 合成数据验收场景

- 版本：0.1（演练草案）
- 日期：2026-10-20
- 范围：只用于本地原型或候选工具的合成数据演练。

## 边界和记录方式

不得导入居民姓名、联系方式、地址、健康信息、真实截图、真实渠道消息或其他可识别个案材料。当前 A+ MVP 使用合成数据，状态保存在当前浏览器 `localStorage`，支持 JSON 全量备份/恢复；本机明文存储和手动备份只服务于合成演练，不是生产工具或真实收件验收。

每轮记录构建/配置版本、前置条件、操作者角色、步骤、预期结果、实际结果、证据位置、审阅者和日期。G0 未定的岗位、时限和阈值先标注为待定，不得用演练者自行设定的值冒充运营批准。

以下任一情况直接判该轮失败：发生外发消息或实际派单；自动创建公开订单或志愿者接单；跨个案泄漏；越权展示或导出字段；关键操作无法归属到操作者；界面误报“已联系、已接收、已升级或已解决”。

## 场景清单

| 编号 | 场景与步骤 | 预期结果 |
|---|---|---|
| A-01 | 未分类通用登记：录入一条合成需求并保存 | 只进入内部待判定队列；有记录编号、责任人、下一步和期限；不公开、不派单、不进入B1 |
| A-02 | 缺少已批准的必要字段或同意状态 | 按批准规则暂停或要求补充；不自行扩大字段采集，不误报已受理 |
| A-03 | 分别用“人工录入演练”和“社区入口演练（仅本机）”建立相同标签或摘要；在重复候选中核对两种来源，填写人工复核说明后确认是否另建独立记录；检查队列、详情及 JSON 备份 | 创建暂停并列出完全重复候选；拟建与候选来源可见；人工确认后保留各自来源、关联记录并追加复核时间线，不静默覆盖或自动合并；旧记录缺少来源时显示“历史来源未记录”；不得连接真实渠道 |
| A-04 | 责任人缺席或超过演练时限 | 显示逾期并形成有记录的人工交接；不伪造联系或结案 |
| A-05 | 模拟转介等待确认、已确认和失败三种结果 | 清楚区分状态；失败回到内部责任人待办；没有确认时不显示已接收 |
| A-06 | 分别演练撤回服务申请与撤回数据处理同意 | 根据已批准的数据处置矩阵分别处理并留痕；未批准时停止演练并报告缺口 |
| A-07 | 投诉对象是当前经办工作人员 | 投诉转给独立复核角色；被投诉人不能自行结案 |
| A-08 | 合成自由文本含高风险线索，分别演练有人值守和无人接手 | 停止普通分诊并提示批准的人工升级路径；无人接手时保留未解决状态并触发停收条件；不自动联系或派单 |
| A-09 | 非值守时段到件或队列超过批准容量 | 按已批准的暂停/待处理规则呈现；不得留下无主记录或作出未批准的响应承诺 |
| A-10 | 弱网、重复点击提交、提交结果未知 | 安全重试不产生重复记录；结果未知时显示待核实并提供人工核对路径 |
| A-11 | 共用账号、无权限角色或访问另一条合成个案 | 标记或拒绝不可归属的操作；权限不足时拒绝访问；个案间数据隔离 |
| A-12 | 错误收件人或尝试查看另一条个案；若图片获批则验证元数据处理 | 阻止错误对象访问；图片默认关闭，获批演练也应验证上传前移除 EXIF/位置元数据 |
| A-13 | 尝试把 A+登记转为公开求助订单、志愿者接单或时长账户 | 不自动转换；显示此功能须经过单独范围、保护和上线批准 |
| A-14 | 演练导出、纠错、删除和备份恢复 | 按已批准的权限/留存矩阵操作并记录操作者、范围和结果；恢复不得意外复活应删除的数据 |
