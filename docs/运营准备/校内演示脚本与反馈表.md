# 校内演示脚本与反馈表

项目背景：学校大创项目，用户本人负责。当前演示版本为方案 B 受控社区，并保留 A+ 登记工作台。

本文是演示准备材料，尚未开展校内演示或收集反馈。全部使用虚构内容；页面角色切换用于模拟流程，不代表真实身份认证或人员授权。

## 演示目标

让观看者判断三个问题：是否看得懂入口、能否完成主要操作、受理和审核流程是否符合预期。项目负责人根据反馈决定下一轮修改顺序。

## 演示前准备

- 打开社区页面 `/community.html` 与 A+ 工作台 `/`。
- 使用单独的演示浏览器环境，准备虚构需求、虚构留言及其处理理由。
- 如要重置或导入数据，先保存当前演示数据；导入会全量替换当前工作台数据。
- 指定一位操作人和一位记录人；人员与演示时间由项目负责人安排。

## 四个任务

| 任务 | 操作路径 | 应展示的结果 | 观察重点 |
|---|---|---|---|
| 1. 发布与审核 | 成员提交一条虚构求助 → 切换审核员处理 → 回到成员页面查看 | 待审内容不进入公共信息流；通过后可见；发布人能查看自身状态 | 能否理解待审状态，能否找到自己的发布记录 |
| 2. 求助协作与举报 | 使用已审核、可接单的虚构求助 → 接单 → 参与者订单留言 → 举报 → 审核员处理 | 留言围绕订单；举报有处理结果；被下架留言对成员隐藏 | 能否找到订单、留言、举报入口；是否理解处理结果 |
| 3. 评论管理 | 提交虚构评论 → 审核通过 → 再下架 | 未审核评论不公开，通过后展示，下架后隐藏；操作理由和日志可追溯 | 评论状态是否清楚，审核理由是否便于填写 |
| 4. 登记与跟进 | 在 A+ 新建通用登记 → 查看重复提示 → 安排负责人和期限 → 添加跟进与处理结果 | 能查看登记来源、当前状态、负责人和跟进记录；保存处理结果不代表真实服务已履约 | 表单是否容易填写，状态和下一步是否清楚 |

每个任务先说明目标，让参与者自行操作。发生卡顿时记录具体步骤，再给予提示。任务失败、需要提示、独立完成应分别记录。

## 从演示进入实际试用

校内演示结束后，先确认服务对象、实际运营组织以及受理、跟进、审核和复核分工，再按 [G0 运营决策登记表](G0运营决策登记表.md) 补齐决定。服务器、身份认证、权限、数据存储和运维准备仍需落实；当前本地原型不承接真实居民登记。

具体学校、指导老师、团队分工和演示日期尚未提供，本文不作默认安排。
