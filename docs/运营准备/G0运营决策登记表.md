## 使用边界

本表签署或填写完成，不等于批准收件、处理真实居民数据、对外联系、服务履约或上线。真实收件至少要先完成工具与流程准备，再分别通过 G1、G2，并由有权运营负责人另行书面批准限定范围的 G3 试点。

当前 A+ MVP 只使用合成数据，状态保存在当前浏览器 `localStorage`，并提供 JSON 全量导入/导出。它没有真实身份认证、生产级权限/审计、受控备份恢复、外发消息或生产运维能力；不得用于真实登记。

每项由适当责任角色单独决定。状态只可填“未决、已确认、已拒绝、不适用”；建议值不构成默认批准。“已确认”须附决定依据、责任人和日期。信息不足时保留未决并写明阻塞阶段。

## 关闸条件

- G0 未完成时，只能继续需求澄清、合成场景和本地原型工作。
- G1 保护与运营准备、G2 数据与技术控制必须分别形成证据和通过结论，不能用一张签字替代。
- 只有有权运营负责人另行签署 G3，且写明社区、人群、登记范围、渠道、人员/容量、周期、指标、停止条件和复核日，才可启动限定的 A+ 真实人工收件试点。
- 无安全容量、无明确的高风险接手路径、或投诉无法独立复核时，不开始真实收件。
- A+试点通过不自动批准 B1 开发、公开任务、志愿者接单、时长账户、紧急推送或其他 B 阶段。

## 工具比较安排

工具比较在 G0 范围和硬性控制要求明确后启动。以当前人工流程/受控表单作为现状基线，候选最多三个。先核对身份与最小权限、个案隔离、可追溯审计、导出/纠错/删除、备份恢复、弱网与幂等、退出和数据可携带、许可/合同等必备门槛；未通过任一适用门槛的候选不进入成本评分。若没有候选达标，暂不选工具。

Coalesce 只可在运营方确认未来需要 B1/B2 后，对对应模块做版本级 fit-gap、许可和代码审查；不作为 A+ 预设底座。TimeOverflow 仅作角色和线上线下业务流程参照，不直接照搬时长规则。
