## 5. 当前状态与角色基线

下表区分现有数据模型和拟补文档；不是本次新实现的状态机。

| 对象 | 当前模型/约束 | 待补说明 |
|---|---|---|
| 帖子、评论 | pending/approved/rejected/hidden；先审后发，保留原文和理由 | 逐条核对可用转换；重提、恢复和申诉不能假定已实现 |
| 求助订单 | open → accepted-local-demo；接单还要求成员及公开审核通过 | 完成、取消、争议、双方确认等后续状态未形成当前履约闭环 |
| 举报 | pending → resolved/dismissed；处理结论不自动下架 | 复核、重开、申诉及办理时限后续确定 |
| 订单留言 | 仅本人参与且已接单的公开审核通过订单；可举报及审核下架 | 真实身份、跨端传输、服务端归属校验待建设 |
| 时长记录 | unsettled，只读演示 | 不将接单或留言直接变成结算 |

| 模拟角色 | 当前演练能力 | 生产差距 |
|---|---|---|
| visitor | 社区正文不展示 | 页面隐藏不能替代服务端访问控制 |
| member | 按公开/审核/参与条件发布、互动、接单与留言 | 真实成员身份和资源归属校验 |
| reviewer | 审核、下架、处理举报并记录理由 | 真实授权、社区隔离、审计保护与职责划分 |

术语约定：帖子是三种发布内容的统称；求助订单才有接单；订单留言不是自由私聊；举报用于内容处置，投诉反馈另行记录；时长记录不等于已结算或可兑换余额。
