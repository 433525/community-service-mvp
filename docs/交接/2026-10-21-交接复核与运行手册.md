## 7. 常见故障

### 7.1 端口占用（preview 起不来 / 打不开）

```powershell
# 谁占了 5180
Get-NetTCPConnection -LocalPort 5180 -State Listen |
  Select-Object LocalAddress, LocalPort, OwningProcess,
    @{n='Process';e={(Get-Process -Id $_.OwningProcess -ErrorAction SilentlyContinue).ProcessName}}
```

本机当前结果：`127.0.0.1 5180 24564 node` —— 这是**别人已经在跑的预览**，不要杀。处理顺序：

1. 只是要看页面：直接用 http://127.0.0.1:5180/ 和 `/community.html`，不要再起服务。
2. 需要自己的实例：`npm run preview -- --host 127.0.0.1 --port 5181 --strictPort`，测试脚本加 `--base=http://127.0.0.1:5181`。
3. `--strictPort` 的语义：端口被占**直接报错退出**，不会静默换端口；看到 `Port 5180 is already in use` 属于预期。
4. 页面 200 但内容是旧版 → 见 7.6「dist 过期」。

### 7.2 `npm run build` 类型错误

- 命令是 `vue-tsc -b && vite build`；`vue-tsc` **成功时无输出**，一旦有输出就是失败，且 `vite build` 不会执行。
- 报错按文件定位；本项目开了 `noUnusedLocals`、`noUnusedParameters`、`erasableSyntaxOnly`、`noFallthroughCasesInSwitch`（`tsconfig.app.json`），常见错误是“多了一个没用的 import/变量”和“用了不可擦除语法（如 `enum`、构造函数参数属性）”。
- 增量缓存位置：`node_modules/.tmp/tsconfig.app.tsbuildinfo`（`tsconfig.app.json:4`）。缓存坏了/切分支后出现幽灵错误时：

```powershell
Remove-Item .\node_modules\.tmp -Recurse -Force -ErrorAction SilentlyContinue
npm run build
# 等价：npx vue-tsc -b --force
```

- 不要用 `npx vite build` 代替构建验收——那会跳过类型检查。

### 7.3 存档 `recovery-required`

A+ 状态栏文案：**「发现无法读取的旧存档，尚未覆盖」**（`src/App.vue:118`）；此时新建/导入会被拦截并提示「旧存档无法读取，请先导出旧存档或恢复备份后再修改。」（`src/stores/intake.ts:342-343`），“社区求助”登记按钮也会被禁用（`src/App.vue:1583`）。

处理顺序（务必按序，不要直接清 key）：

1. 点「下载无法读取的旧存档」（`src/App.vue:1247`，下载 `a-plus-unreadable-local-save.txt`），确认文件落盘。
2. 再决定：「导入备份」恢复，或「重置演练」覆盖（重置前会二次确认，提示“重置会覆盖这份原文且无法恢复”）。
3. B 端同理：我的 → 存档卡 → 「下载原始存档」（`ProfileView.vue:185-191`）→ 再「重置演练数据」。B 的 recovery 状态会**停止全部写入**，避免覆盖原文。

排查辅助：A+ 存档原文在 `a-plus.synthetic-intake.v1`；若 `JSON.parse` 抛错，就是被手工改坏或写了非 JSON 内容。**直接 `localStorage.removeItem` 会永久丢掉原文**，只在确认不需要时使用。

### 7.4 筛选偏好异常

先分清“偏好丢了”还是“默认值本来如此”：

- A+ 队列筛选键 `a-plus.intake-filter.v1`；非法值/缺失都会回退 `全部记录`（`src/intake-filter-preference.ts:22-28`）。没有 UI 重置按钮，切到「全部记录」即写回。
- B 审核筛选键 `community-mvp.moderation-filters.v1`；**默认 `comment=pending`、`report=pending`**（`moderation-filters.ts:22-28`）——很多人会误以为“评论/举报筛选坏了”，其实是默认只看待审。
- 逐字段非法值会各自回退默认（`moderation-filters.ts:36-59`），所以“只有一个筛选不对”通常是键内容被手工改过。
- 修复：审核页「重置筛选」，或 `localStorage.removeItem('community-mvp.moderation-filters.v1')` 后刷新。**这些键与存档完全分离**，清它们不会丢帖子/订单/记录。
- 注意：审核**搜索词**、消息页搜索、A+ 搜索都不持久化（内存态），刷新即清空，这是设计如此，不是 bug。

### 7.5 弹层焦点异常

- A+：所有弹层由 `src/App.vue` 统一管理 —— 打开时焦点进入、`Tab` 在弹层内循环、`Esc` 关闭、关闭后焦点归还触发按钮，背景 `:inert="anyDialogOpen"`（`App.vue:1176`、`1196`；焦点逻辑在 `App.vue:464-510`）。新建记录弹层标题 id 为 `create-title`。
- B：「? 说明」弹层（`aria-labelledby="community-help-title"`，`src/community/App.vue`）与首页安全说明弹层（`aria-labelledby="safety-title"`，`src/community/views/HomeView.vue:160`）都自带 Esc 关闭 + 焦点归还，背景有 `inert` 绑定；弹层打开时页面标题/底栏不参与 Tab。
- 排查清单：`role="dialog"` 是否存在、`aria-modal="true"`、`aria-labelledby` 指向真实 id、背景是否 `inert`、Esc 后弹层是否真的移除（**不要假设 Esc 之后还能点关闭按钮**，这正是 `audit-a11y.mjs` 的中断原因）、焦点是否回到触发元素。
- 复验命令：`node tools\check-fixes2.mjs --base=http://127.0.0.1:5180`（10/10 含 A+/B 弹层与 390px）。

### 7.6 其他常见现象

| 现象 | 判断 | 处理 |
| --- | --- | --- |
| 页面空白 / 是旧版 | dist 比 src 旧，或 preview 是旧进程 | 重新 `npm run build`，重启 preview 并强制刷新 |
| A+ 提示「其他窗口已更新存档，请重新载入」 | 多标签冲突（`conflict`） | 点「重新载入最新存档」，不要在旧标签继续写 |
| 状态「本机存档写入失败」 | `save-error`（配额/隐私模式） | 导出备份后重试；记录不会被伪造为已保存 |
| 「当前不可用本机存档」 | `memory-only` | 数据只在本次会话，刷新即丢，先导出 |
| 发布草稿恢复了但“虚构内容确认”没勾 | 设计如此（`publish-draft.ts` 不保存该勾选） | 提交前必须重新勾选 |
| 刷新后 B 的演练身份变回“访客” | 设计如此：`membership` 不写入存档（`store.ts:688` 注释明确“never persisted”） | 需要成员能力时重新切换身份 |
| 深链“去社区动态处理”刷新后丢失 | 设计如此（不写 URL） | 从「我的 → 服务记录」重新进入 |
| A+ 演示角色切换后权限没变 | 角色仅演示，不构成鉴权 | 不要据此做权限判断 |
| `audit-a11y.mjs` 跑到 A+ 弹层就退出 | 已知脚本缺陷 | 用 `check-fixes2` 复验 A+ 弹层 |
| `audit-aplus.mjs` 备份组大量 FAIL | 证据来自 20:36–20:37，早于修复 | 若要现状结论，重跑并保存新证据 |

### 8.2 表述不准确 / 易误导（建议改）

**W1｜§4 注意事项“脚本按顺序跑，避免多脚本同时清空/写入同源 localStorage”**
