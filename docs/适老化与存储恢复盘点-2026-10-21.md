## 0. 结论摘要

### 0.1 先确认的既有保护（避免误报为缺失）

适老化与移动端方面已有：

- `lang="zh-CN"`、`<title>邻里 · 社区服务演练版</title>`；viewport 允许缩放，未设置 `user-scalable=no`（`a-plus-app/community.html:2-8`）。
- `body { min-width: 320px }`（`style.css:20`），明确以 320px 为最窄目标。
- 全局键盘焦点样式：`button/input/textarea:focus-visible` 3px 描边（`style.css:23`），开关另有焦点样式（`style.css:270`）。
- 大量非颜色兜底：审核状态、订单状态、报名状态、账本“未核验”、存档状态、筛选选中（`aria-selected`）均有文字说明，不只靠颜色。
- 减弱动效支持：`@media (prefers-reduced-motion: reduce)` 全局压缩动效时长（`style.css:548-550`）。
- 可访问性基础：`.sr-only` 隐藏标签（`style.css:407`）、搜索框 `aria-label`、收藏/关闭按钮 `aria-label`、`role="tablist"`、导航/侧栏 `aria-label`、toast `role="status" aria-live="polite"`（`App.vue:135`）、发布页错误 `role="alert"`（`PublishView.vue:85`）、安全说明弹窗 `role="dialog"`（`HomeView.vue:102`）。
- 新增履约闭环 UI 有部分适老化改善：订单操作按钮移动端 `min-height: 44px`（`style.css:610`）、订单状态胶囊“圆点 + 文字”（`style.css:563-564`）、订单/时间线区域 `aria-label`（`PostCard.vue:211`、`MessagesView.vue:70`）、存档 JSON 文本框 `readonly + aria-label`（`ProfileView.vue:198`）。
- 存储方面已有：损坏存档保留原文、阻断写入、提供原始存档下载；写失败不应用半成品状态；多标签变化检测与拒写；“覆盖损坏存档”二次确认；旧存档缺省字段归一（审核状态默认待审、可选项默认空）；新增本机存档 JSON 只读导出。

### 0.2 主要风险（本文结论）

1. **字号远低于适老目标**：正文、说明、输入框普遍 8–12px，移动端进一步降到 8–9px；根字号未设、几乎全部使用 px，无法随浏览器/系统字号放大。
2. **触控目标普遍不足 44px**：点赞、评论、举报、筛选、收藏、重置、关闭等高频控件约 20–38px。
3. **关键说明对比度不足**：合成数据横幅 3.96:1、存档说明 2.85:1、隐私说明 2.57:1、页脚/日期 2.18–2.63:1，低于普通小字 4.5:1 要求；焦点环 2.05–2.22:1 低于 3:1。
4. **键盘焦点被局部移除**：搜索框 `outline: 0` 覆盖了全局焦点样式；弹窗无初始焦点/焦点圈定/Esc 的证据（静态推断）。
5. **存储故障“有保护、难发现、难恢复”**：应用启动时读到损坏/超限存档只在“我的”页有通用提示；具体原因（JSON 非法/版本不支持/超限/字段无效）保存在 `storageError` 但界面未渲染；容量拒绝后状态可能仍显示“已保存”；提示“清理部分演练数据”但 B 没有单条删除入口，只能整库重置。
6. **帮助/错误提示未形成闭环**：没有帮助页或“数据说明”入口；多数操作错误只在 2.8 秒 toast 中出现；长恢复文案（约 60–70 字）在 toast 中一闪而过，不适合老年用户阅读。

### 1.5 键盘焦点可见性

**实际证据**

正向：

- 全局 `:focus-visible` 3px `#87b89a`、offset 3px（`style.css:23`）；开关 `:focus-visible + .switch`（`270`）。
- 交互元素基本是原生 `<button>`，Tab 可达、Enter/Space 可用；`.sr-only` 提供隐藏标签（`style.css:407`；`PostCard.vue:248`；`MessagesView.vue:77`）。

风险：

- **搜索框焦点环被移除**：`.search-box input { outline: 0 }`（`style.css:224`）与 `input:focus-visible`（`23`）特异性相同且源序在后，会覆盖全局焦点环；首页与社区页两个搜索框受影响（`HomeView.vue:64`、`CommunityView.vue:41`）。
- 焦点环颜色对比不足 3:1（见 1.4）。
- `select` 不在全局 `:focus-visible` 覆盖内：`App.vue:110` 演练身份选择、`style.css:555` 未移除 UA 默认 outline（预计仍有默认环，但与本应用样式不一致；未实测）。
- `.field-label input/textarea { outline-color: #8eaf91 }`（`style.css:252`）：若浏览器使用 `outline: auto`，环颜色会变为 2.37:1 的低对比色（静态推断）。
- 自建弹窗与组件弹窗焦点管理未证实：安全说明弹窗有 `role="dialog" aria-modal="true" aria-labelledby`（`HomeView.vue:102`），但未见初始焦点、Esc 关闭、焦点圈定；`style.css:208` 的 `.modal-backdrop + * { pointer-events: none }` 因遮罩是容器最后一个子节点而基本无效，键盘仍可到达背景内容。重置确认使用 Vant `showConfirmDialog`（`ProfileView.vue:136-144`）：库内可静态看到 `role="dialog"`、`aria-labelledby`、`tabindex="0"`，未见 `aria-modal` 和自动聚焦；`Esc/Enter` 仅在焦点位于弹窗自身时生效（`node_modules/vant/es/dialog/Dialog.mjs:75-89`）——均未在浏览器验证。
- `role="tablist"/"tab"`（`HomeView.vue:68-71`、`CommunityView.vue:41`、`ProfileView.vue:203-205`）没有方向键切换、没有 `tabpanel`/`aria-controls`，ARIA tabs 模式不完整（按钮本身仍可 Tab 到达）。
- 切换页签后焦点停留在导航按钮，没有把焦点移到新页面标题，也没有路由变化播报；页面无 skip link。

**结论：存在风险。** 全局焦点样式存在属于既有保护；但搜索框焦点被移除、焦点环对比不足属于静态可确认的缺陷，弹窗焦点行为未验证。

**建议**：删除 `.search-box input` 的 `outline: 0`，用统一 focus-visible token（3px、≥3:1、offset 2–3px）覆盖 `a/select/summary` 等元素；为自建弹窗补初始焦点、Esc 关闭、焦点圈定并恢复背景 `inert`；使用并验证成熟组件弹窗的键盘行为；tabs 要么补方向键与 tabpanel，要么降级为普通按钮组；页签切换后聚焦主标题并加 `aria-live` 播报。

### 1.6 非颜色状态提示

**实际证据**

正向（不依赖颜色也可理解）：

- 审核状态徽标有文字“待审核/审核通过/已驳回/已下架”（`PostCard.vue:188`）。
- 订单状态胶囊“圆点 + 完整文字”（`PostCard.vue:213`、`style.css:563-564`）；状态行内文字（`PostCard.vue:195`）。
- 报名状态有文字“我已演练报名”（`PostCard.vue:201`）。
- 时长账本“未核验”（`ProfileView.vue:255`）、服务记录文字状态（`235`）、存档状态文字（`192`）、系统通知“合成示例”（`MessagesView.vue:83`）。
- 筛选/页签选中同时用背景、边框、加粗与 `aria-selected`（`style.css:219-220`、`CommunityView.vue:41`、`ProfileView.vue:204`）。

缺口：

- 点赞按钮选中态只有颜色 `.chosen { color: #ba735b }`（`style.css:183`），图标固定“♡”、没有 `aria-pressed`（`PostCard.vue:204`）；B 端源码中没有 `aria-pressed`/`aria-current` 的任何使用。
- 移动底栏当前项只有颜色 + `font-weight: 700`（`style.css:542`），没有 `aria-current="page"`（`App.vue:124-134`）。

**结论：存在风险。** 主要状态机制有文字兜底（正向）；点赞、移动底栏两处依赖颜色/字重。

**建议**：点赞改为 `aria-pressed` + 图标/文案变化（如“❤/♡”或“已赞”）；底栏当前页加 `aria-current="page"`；后续新增状态继续坚持“文字为主、颜色与图标为辅”。

### 1.7 底部安全区

**实际证据**

- `.mobile-nav` 使用 `padding: 5px 7px max(7px, env(safe-area-inset-bottom))`（`style.css:540`）。
- `.community-app` 移动端 `padding-bottom: 82px`（`style.css:423`）；`.toast-message` 移动端 `bottom: 78px`（`545`）。
- `community.html:5` 的 viewport **没有 `viewport-fit=cover`**，iOS 上 `env(safe-area-inset-*)` 通常取 0（静态推断），这意味着现有安全区写法可能实际未生效。
- `.toast-message` 定位未计入安全区；`body/.community-app/.app-frame` 使用 `100vh`（`style.css:20`、`25`、`431`），移动浏览器地址栏会导致视口变化。

**结论：存在风险（安全区适配可能实际上是空实现）；未在真机验证。**

**建议**：二选一——加 `viewport-fit=cover` 并补齐四边安全区（底栏、toast、弹窗），或移除误导性的 `env()` 写法；toast 定位改为 `calc(78px + env(safe-area-inset-bottom))`；考虑 `100vh → 100dvh`。

### 1.8 动效 / 减弱动效

**实际证据**

- 过渡用于导航、按钮、快捷卡片、开关、toast：`style.css:44`、`81`、`107`、`266-267`、`206-207`。
- `@media (prefers-reduced-motion: reduce)`：把 `animation-duration`/`transition-duration` 压到 `.01ms` 并关闭平滑滚动（`style.css:548-550`）。
- 新增履约与存档面板未见新的关键帧动画或自动播放。

**结论：静态已确认（正向）。** “提供减弱动效”这一点源码成立；实际系统设置生效与否未在浏览器验证。

**建议**：保留该策略；新增过渡沿用同一规则；不要仅靠动画传达状态。

## 2. 存储故障路径核对

> **测试未运行：以下全部为源码阅读推断，未做 localStorage 故障注入、未复现任何一条路径，不能当作实测结果。**
> 存储键/版本：`storage.ts:4-5`（`community-mvp.synthetic-state.v1`、`schemaVersion: 1`）；状态枚举：`types.ts:148-157`；文案常量：`store.ts:61-68`；容量与数量上限：`store.ts:70-79`；入口函数：`loadInitialState`（`store.ts:493-552`）、`persistState`（`668-731`）、`reloadFromStorage`（`733-776`）、`parseStoredCommunity`（`452-483`）。

### 2.1 损坏存档（非 JSON / 格式无效 / 字段无效 / 超限）

**实际代码行为**：`loadInitialState` 读取 `localStorage` 后调用 `parseStoredCommunity`；任一类解析失败都会返回 `ok:false` 与具体错误，随后状态置为 `recovery-required`，内存回退到初始合成 fixtures，原始字符串保存在 `unreadableStoredData` 并作为写基线；所有写操作在 `persistState`/`blockedByRecovery` 处被拦截，返回统一恢复提示。

**提示文案位置**：

- 常量 `RECOVERY_REQUIRED_MESSAGE`：`store.ts:61-62`——“本机有一份无法读取或版本不受支持的社区演练存档。为避免覆盖原文，已停止所有写入；请先备份原文，或明确使用‘重置演示数据’。”
- 具体原因：`store.ts:452-476`（超限 / 非 JSON / 格式无效 / 版本不受支持 / 字段无效），保存在 `storageError`（`633`、`761-767`）。
- 可见界面：`ProfileView.vue:190-194` 存档卡通用文案“存档需要处理，原始内容已保留；当前不能写入。”；`ProfileView.vue:192` 的“下载原始存档”按钮；下载实现 `ProfileView.vue:118-131`（Blob 下载 `community-unreadable-local-save-YYYY-MM-DD.json`，并提示先保存再决定是否重置）。

**缺口（静态确认）**：

- B 端界面没有任何位置渲染 `storageError` 与 `lastSavedAt`（B 端源码中仅 store 内部使用），用户看不到“到底是 JSON 坏了、版本不支持还是超限”。
- 应用启动时读到损坏存档**没有全局提示**：只有用户主动进入“我的”才能发现；其他页面看起来仍可操作，直到某次操作失败才弹 toast。
- 恢复入口只有“我的”页。

**结论：存在风险。** 保护机制完整（保留原文、阻断写入、可下载、可重置），但发现性与原因说明不足。

### 2.2 超容量（读取侧与写入侧）

**实际代码行为**：

- 读取：`raw.length > 1_000_000`（`MAX_STORED_CHARS`）→ `store.ts:453-455` 返回“社区演练存档超过大小上限，已保留原文且不会自动覆盖。”→ 进入 `recovery-required`，写入全停。
- 写入：序列化后 `serialized.length > 1_000_000` → `store.ts:711-715` 拒绝写入，返回“本次操作会生成超过 1000000 字符的本机存档，已拒绝写入且旧存档保持不变；请清理部分演练数据后再试。”；不调用 `applyState`，旧存档与内存状态不变。

**缺口（静态确认）**：

- 容量拒绝路径**不设置** `storageStatus`（仍是 `saved` 或原状态），Profile 仍可能显示“已保存到当前浏览器”，与“本次未写入”不一致；错误只出现在 toast。
- 提示让用户“清理部分演练数据”，但 B 端没有删除单条帖子/评论/留言的入口，只能“重置演练数据”整库清空；提示不可执行。
- 数字 `1000000` 未做千分位/换算（如“约 1MB”），对老年用户不友好。
- 未做写入前容量预估与可用空间探测，配额耗尽仅能通过 `setItem` 抛错被动发现。

**结论：存在风险。** 拒绝写入与保护旧档成立；提示可执行性、状态一致性不足。

### 2.3 版本不受支持 / 旧存档兼容

**实际代码行为**：

- `app`、`kind` 或 `schemaVersion !== 1` → “社区演练存档版本不受支持，已保留原文且不会自动覆盖。”（`store.ts:467-473`）→ `recovery-required`，写入全停。
- 旧存档兼容（正向）：
  - 缺少审核字段的旧帖子/评论统一归为 `pending`（`normalizePost`/`normalizeComment`，`store.ts:348-360`、`366-375`），不会自动公开；
  - `reports`、`auditLog` 为可选项，缺失时默认空数组（`types.ts:285-294`、`store.ts:372-373`）；
  - 新增 `orderEvents` 也是可选字段，旧存档可缺省（`types.ts:213-214`、解析校验 `store.ts:227-238`、`400-404`）；
  - 重置时用全新帖子 ID 重建 fixtures（`resetFixturesWithFreshPostIds`），避免旧 ID 冲突。
- 业务层兼容提示示例：旧活动缺 `volunteerKind` 时报名被拒绝并给出说明（`store.ts:1540-1542`），而不是静默失败。

**缺口（静态确认）**：没有 `schemaVersion` 升级/迁移函数，也没有“导入旧存档并升级”的入口；未来一旦提升版本，用户只能下载原文后重置，无法把旧数据迁移回来。

**结论：存在风险。** 同版本旧存档兼容较好；跨版本迁移缺失。

### 2.4 多标签冲突

**实际代码行为**：

- 监听 `window.storage`（`store.ts:778-785`）：其他标签写入且 `event.newValue !== lastKnownRaw` 时，置 `conflict` 并写 `CONFLICT_MESSAGE`（`67-68`），**不发 toast，当前页面上也没有除“我的”页以外的提示**。
- 写保护：`persistState` 写前用 `getItem` 与 `lastKnownRaw` 比较，不一致即拒绝（`704-708`），返回冲突文案。
- 恢复：`ProfileView.vue:192` 冲突态显示“重新载入”按钮，`reloadData`（`113-116`）调用 `reloadFromStorage`；重载先把 `lastKnownRaw` 更新为新基线（`750-751`），再解析应用。

**缺口（静态确认）**：

- 冲突发生时用户可能在别的页签/页面，写入失败前无感知；必须到“我的”点“重新载入”。
- `check-then-write` 不是原子锁：两个标签页同时通过检查后先后写入，仍可能后写覆盖先写（交接文档已注明“不能称为生产并发控制”）。
- 冲突状态下点击重置会先因 `currentRaw !== lastKnownRaw` 被拒（`persistState` 冲突分支先于 `allowRecovery` 生效），用户需要先重载——UI 未说明这一顺序。

**结论：存在风险。** 检测与拒写成立；提示时机、恢复路径与并发保证有限。

### 2.5 写入失败 / 存储不可用

**实际代码行为**：

- `getItem`/`setItem` 抛错 → `save-error` + `SAVE_ERROR_MESSAGE`（`store.ts:65-66`、`699-702`、`716-722`）；不调用 `applyState`，界面保持上一次成功保存的状态（与文案“本次操作未应用”一致）。
- `localStorage` 不可用（`getLocalStorage()` 返回 null 或抛错）→ `memory-only`：状态仅在内存应用，返回 `MEMORY_ONLY_MESSAGE`（`63-64`、`683-693`），Profile 显示“当前只能保存在本次会话，刷新后可能丢失。”
- 恢复后（成功写入）状态回到 `saved` 并清空 `unreadableStoredData`（`724-730`）。

**结论：静态已确认（正向）。** 错误分支与提示文案一致、无半应用；未实际触发配额错误验证。

**缺口**：写入失败同样只 toast + “我的”卡片，其他页面无持久提示；失败后没有“重试”按钮（需再次执行原操作）。

### 2.6 恢复 / 重置确认

**实际代码行为**：

- 重置入口：`ProfileView.vue:193` “重置演练数据” → `resetData`（`133-151`）→ Vant `showConfirmDialog`：
  - 损坏/不可读时：标题“覆盖损坏存档并重置？”，正文“当前存档无法读取或版本不受支持。重置会覆盖这份损坏存档，覆盖后无法恢复；如需保留原文，请先‘下载原始存档’。确认覆盖并恢复初始虚构示例吗？”，确认按钮“覆盖并重置”（`137-143`）。
  - 正常时：标题“恢复演练数据？”，正文“本机新增的帖子、互动和反馈将被初始虚构示例覆盖。”，确认按钮“恢复数据”。
  - `confirmButtonColor: '#2e6b52'` 统一为绿色（非危险色）。
- 执行：`resetDemoData`（`store.ts:2024-2030`）以 `allowRecovery: true` 写入全新 ID 的 fixtures，成功提示“已恢复为虚构演示数据。”
- 重新载入：无存档时加载初始 fixtures（`752-759`），成功提示“已重新载入最新本机存档。”（`775`）。
- 只读导出（新增，正向）：`readBackupJson`（`store.ts:2036-2038`） + `ProfileView.vue:196-200` “本机存档 JSON（只读快照）”、只读 textarea、复制 JSON；复制失败有兜底提示（`165-172`“复制失败：请在下框内全选后手动复制。”）。该导出**不会写回、不会上传**。

**缺口（静态确认）**：

- 破坏性“覆盖并重置”使用绿色品牌色确认按钮，未使用危险样式/二次输入确认。
- 正常重置对话框没有提示“可先查看/复制存档 JSON”（虽然该功能就在同一页面）。
- 重新载入/下载原始存档/查看存档 JSON 入口都集中在“我的”页，其他页面无入口。
- 确认弹窗静态代码未见 `aria-modal` 与焦点管理（见 1.5），键盘行为未验证。
- 只有查看/复制/下载（损坏原文）能力，没有“导入存档恢复”入口；健康存档无法通过应用内操作恢复。

**结论：存在风险。** 确认文案充分、保护动作正确；破坏性样式、键盘可达性、入口集中与导入恢复不足。

### 2.7 既有保护汇总（避免误报缺失）

1. 损坏存档：保留原文 + 阻断全部写入 + 下载原文 + 明确覆盖警告。
2. 容量：读写两侧均有上限检查；写入拒绝时旧存档保持不变。
3. 版本：不支持版本时拒绝加载并保留原文；同版本缺省字段做安全归一（旧内容不自动公开）。
4. 多标签：`storage` 事件检测 + 写前基线比较拒绝覆盖 + 手动重载基线。
5. 写失败：不应用半成品状态；内存不可用时降级为 memory-only 并明确提示。
6. 重置：二次确认、区分损坏/普通两种文案、重置后使用新 ID 的初始数据。
7. 只读导出：新增存档 JSON 只读快照与复制，不写回、不上传。
8. A+ 受理进度读取器只读、不修复不覆盖（`intake-progress.ts:42-88`；`ProfileView.vue:225-233` 明确“本页不会修改或覆盖它”）。

### 2.8 本节未覆盖项

- 未做 localStorage 损坏注入、配额写满、`setItem` 抛错、多标签并发写、隐私模式、清空站点数据等实际触发。
- 未验证 `storage` 事件在真实浏览器/多标签下的时序。
- 既有浏览器记录不能替代：`docs/运营准备/2026-10-21-B主流程实测.md` 第 39 行明确“跨标签冲突、刷新恢复、存储满或损坏……未在本轮完整验证”。

### 3.2 横切结论

- **持续区分合成演示与真实受理：整体较强**（常驻横幅、页面文案、按钮/状态命名“演练”、通知“合成示例”），未发现把合成操作写成真实受理的页面；这不是当前主要缺口。
- **“发生了什么 → 如何恢复 → 去哪里”未形成统一模板**：损坏/超限/版本/冲突的具体原因在 store 有区分，界面只显示通用文案；恢复动作集中在“我的”，其他页面无跳转；错误提示格式在 inline alert（发布页）与 transient toast（其余）之间不统一。
- **toast 承载了过多关键错误**：`App.vue:36-37` 固定 2800ms 后清空，无法暂停、无历史记录；对老年用户和读屏用户都不友好（虽然有 `aria-live`，但长文本很可能播报不完）。
- **没有任何“帮助/FAQ/数据说明”页面或常驻入口**：DOC-06 的“帮助入口”要求在现有界面中缺失。
- **正向**：A+ 受理进度面板是本项目里“说明发生了什么 + 本页不会覆盖它”的较好示例（`ProfileView.vue:225-233`），可作为错误提示文案的模板参考。

## 4. 按阻断程度的修复建议（只建议，不改代码）

### 4.1 P0（建议优先处理：直接影响老年用户可读可用）

1. **放大正文与关键说明**：正文/说明 ≥16px、辅助 ≥12–14px、输入控件 ≥16px，并使用 rem 支持浏览器字号放大；至少先覆盖帖子正文、订单/存档说明、错误与隐私提示、表单输入。
2. **触控目标 ≥44×44**：点赞/评论/举报/收藏/筛选/搜索/收藏/重置/关闭/存档面板按钮/移动底栏；用 padding 或伪元素扩大命中区，不必放大视觉。
3. **关键文字对比度达标**：合成数据声明（3.96）、存档说明（2.85）、隐私说明（2.57）、页脚/日期/状态小字（2.18–2.63）提升到 ≥4.5:1；焦点环提升到 ≥3:1。

### 4.2 P1（建议在下次功能完善中处理）

4. **存储状态全局可见 + 具体原因 + 恢复路径**：在全局壳或各页显示存档状态；渲染 `storageError` 与 `lastSavedAt`；损坏/冲突时提供“去我的页处理”快捷入口；启动时若为 recovery-required 立即提示。
5. **容量/上限提示可执行**：容量拒绝时设置明确的“未保存”状态并停止显示“已保存”；提供单条删除/清理入口或说明“先导出 JSON 再重置”；数字格式化。
6. **键盘焦点与弹窗焦点管理**：移除 `.search-box input` 的 `outline: 0`；统一焦点环 token；补 `select` 等元素；自建弹窗补初始焦点/Esc/Trap/背景 inert；验证 Vant 确认框键盘行为并补 `aria-modal`。
7. **非颜色状态补齐**：点赞 `aria-pressed` + 图标变化；移动底栏 `aria-current="page"`。
8. **帮助入口与错误文案统一**：新增“帮助/数据说明”入口（可用轻量弹窗或折叠面板，说明合成数据、保存位置、恢复/重置、错误含义）；错误统一为“发生了什么 → 如何恢复 → 去哪里”；长错误改为持久内联提示，不只用 toast。
9. **tabs 语义**：补方向键与 `tabpanel`/`aria-controls`，或降级为普通按钮组，避免宣布为 tab 却无 tab 键盘行为。

### 4.3 P2（可排后或随版本迭代）

10. **安全区**：加 `viewport-fit=cover` 并补齐安全区，或移除空的 `env()`；toast 定位加 `env()`；`100vh → 100dvh`。
11. **320–430 专项**：补 320/375/390/430 实测与溢出检查；最窄屏把 3 列摘要/发布类型改 2 列或纵向；确认 topbar 窄屏表现。
12. **版本迁移预留**：为 `schemaVersion` 升级准备迁移函数与“旧存档可升级”的提示/入口，避免升级即锁死。
13. **重置确认改进**：破坏性操作使用危险样式/二次输入；正常重置时提示可先“查看/复制存档 JSON”。
14. **存档导入/恢复**：当前只有查看/复制/下载，建议补“导入存档”校验流程（同样需版本与上限校验）。
15. **文案维护**：状态文案在 store 常量与 Profile/其他组件中各有一份，建议收敛为单一来源；统一日期时间格式。
16. **装饰元素**：纯装饰图标补 `aria-hidden`（如快捷入口箭头、头像字符），减少读屏噪音。
