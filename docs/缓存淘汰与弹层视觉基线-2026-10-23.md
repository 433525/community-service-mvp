# 缓存淘汰与 A+ 弹层视觉基线（2026-10-23，第 7 轮）

本轮两个增量：Service Worker 运行时缓存的淘汰与配额自愈；A+ 业务弹层纳入视觉回归基线。

## 参考与依据

- Workbox 官方文档《Understanding storage quota》与《Caching resources during runtime》：
  `ExpirationPlugin` 三段语义 —— `maxEntries`（条目上限，超量从最旧淘汰）、
  `maxAgeSeconds`（最长期限）、`purgeOnQuotaError`（配额写满时允许清空缓存后重试）。
- MDN《QuotaExceededError》：现代形态 `name === 'QuotaExceededError'`，旧式 `code === 22`，
  部分实现只有 message，判定函数三种都覆盖。
- 不引入 Workbox 依赖（本项目零依赖原则），在 `public/sw.js` 手写等价实现；
  与 Workbox 的差异：元数据不走 IndexedDB，改为写入响应头 `x-sw-cached-at`
  （同源响应可读可改，SW 重启后仍保留），淘汰时按该时间戳排序。

## 变更

### 1. 运行时缓存淘汰（`public/sw.js` + `src/shared/cache-expiration.ts`）

- 常量口径：单缓存运行时条目上限 **64**，最长期限 **7 天**，时间戳头 `x-sw-cached-at`。
  `cache-expiration.ts` 是纯函数版本（可单测），sw.js 内手工同步同名常量（文件内已注明）。
- `putQuietly` 写入前加盖时间戳头（`stampResponse`，基于 `response.clone()`，不影响原响应）。
- `trimCache(cache)` 两段式淘汰：先删全部过期条目；剩余仍超限时按时间戳从旧到新删到不超限，
  时间戳相同按路径字典序，结果确定。**预缓存条目永不参与淘汰**（删了会破坏离线可用）。
- 配额自愈（`purgeOnQuotaError` 等价）：`cache.put` 抛配额错误时，先把运行时条目清空
  （`trimCache(cache, { maxEntries: 0 })`）再重试一次；重试仍失败则放弃本次写入，响应照常返回。
- `activate` 时顺手做一次家政；新增 `TRIM_CACHE` 消息通道，页面/回归脚本可主动触发，
  结果以 `TRIM_CACHE_DONE` 回发来源。
- 时钟回拨不误删：`now < cachedAt` 视为新鲜；时间戳缺失/非法视为过期（无法证明新鲜就当不新鲜）。

### 2. A+ 业务弹层视觉基线（`tools/check-visual.mjs`）

- 基线 11 → **15 个状态**，新增（均 1440 桌面）：新建演练记录、更新登记状态、标记高风险、提交演示投诉。
- **基线稳定性修复**：`defaultDueDate()` 是「今天 +2 天 17:00」，逐日变化会让含
  `datetime-local` 的弹层截图每天哈希不同。截图前把 `#record-due` / `#transition-due`
  钉成固定值 `2026-10-25T17:00`（只改渲染值，不触发 v-model）。这是本轮发现并排除的
  一个会随时间漂移的假阳性来源。
- 原有 11 张基线重建后逐张比对 SHA-256，**全部不变**（备份比对，非仅信任脚本输出）。
