# 部署说明（2026-10-22）· a-plus-app 静态可部署性收口

> 适用范围：**仅覆盖「能不能作为一个纯静态站点被正确托管」**。
> 本文件 **不代表** 该项目已可公开发布 —— 公开发布前必须先解决第 9 节的 G3 阻塞项。
> 本次工作没有部署、没有绑定域名、没有改 DNS、没有提交 Git。

---

## 1. 目标形态

| 项 | 取值 |
| --- | --- |
| 托管形态 | 纯静态文件托管（CDN / 对象存储 / 静态站点平台均可） |
| 部署路径 | **域名根路径 `/`**（不可用子路径，见第 8 节） |
| 服务端 | 无（无 Node/PHP 进程、无接口、无 SSR） |
| 数据库 | 无（无任何持久化后端） |
| 运行时数据 | 全部存 `localStorage`，按 **origin** 隔离 |
| 外部依赖 | 无 CDN、无外部字体、无第三方脚本、无网络请求 |
| 入口 | `/`（A+ 工作台，`index.html`）、`/community.html`（邻里社区演练） |
| 路由 | 无前端 router；两个 HTML 是真正的多页入口，**不需要也不需要配置 SPA catch-all 重写** |

`localStorage` 按 origin 隔离的直接后果，写清楚以免被当成 bug：

- 换域名、换端口、换协议（`http` ↔ `https`）都会看到一份**空数据**，旧数据仍留在旧 origin 里。
- 演练数据不会、也无法在浏览器之间或设备之间同步；清浏览器数据即销毁。
- 因此**不能**把「演练进度」当作可迁移成果；对外演示前请在目标 origin 上重新导入数据。

## 2. 构建与发布步骤

前置：Node ≥ 20（本机验证 Node v22.22.2），`npm ci` 已有 `node_modules` 时可直接构建。

```bash
# 1) 构建（vue-tsc 类型检查 + vite 打包，产物 dist/）
npm run build

# 2) 自检：产物齐全 / 引用可解析 / 无外链 / robots 与 404 / 预览可达
node tools/check-deployability.mjs --base=http://127.0.0.1:5180

# 3) 本机预演最终产物（可选；注意 vite preview 默认 4173，与开发端口 5180 无关）
npm run preview

# 4) 上传 dist/ 的**全部内容到站点根目录**（不是上传 dist 这一层目录本身）
```

发布产物清单（`dist/`）：

```
dist/index.html            入口 A（/）
dist/community.html        入口 B（/community.html）
dist/404.html              兜底页（不引用 /assets/*，样式内联）
dist/robots.txt            整站禁止抓取
dist/favicon.svg           未带哈希（不要设 immutable）
dist/icons.svg             未带哈希（不要设 immutable）
dist/assets/*              JS/CSS，文件名含内容哈希
```

注意：

- `dist/` 被 `.gitignore` 忽略，**产物不进版本库**；每次发布都必须先构建。
- 上传时保持目录层级：站点根 = `dist/` 的内容，`/assets/xxx.js` 必须能直接访问。
- 构建日志里若出现 `Ignoring extra certs from ...pem, load failed`，那是本机环境的 CA 变量噪声，与产物无关。

## 3. MIME 类型（必须正确，否则模块脚本直接不执行）

| 扩展名 | Content-Type | 备注 |
| --- | --- | --- |
| `.html` | `text/html; charset=utf-8` | UTF-8 必须声明，页面含中文 |
| `.js` | `text/javascript; charset=utf-8` | **不能**返回 `text/plain`/`application/octet-stream`，`<script type="module">` 会被浏览器拒绝执行 |
| `.css` | `text/css; charset=utf-8` | — |
| `.svg` | `image/svg+xml` | favicon 与图标 |
| `.png` | `image/png` | — |
| `.txt` | `text/plain; charset=utf-8` | `robots.txt` 必须是 UTF-8 纯文本 |

## 4. 缓存策略

| 路径 | Cache-Control | 理由 |
| --- | --- | --- |
| `/assets/*` | `public, max-age=31536000, immutable` | 文件名含内容哈希，内容变则文件名变，可永久缓存 |
| `/`、`/index.html`、`/community.html`、`/404.html` | `no-cache, must-revalidate` | HTML 是「版本指针」，必须每次回源校验，否则新版本发不出去 |
| `/robots.txt` | `no-cache` | 体积小，且需要能随时收紧/放开 |
| `/favicon.svg`、`/icons.svg` | `public, max-age=604800` | **未带哈希，禁止 immutable**，否则改图后用户长期看不到新版 |

发布顺序上的硬约束：**新 HTML 与新的 `assets/` 必须同一次发布原子生效**。若只更新 HTML 而后端还没同步新 chunk，用户会拿到 404 的 JS；若只更新 assets 而 HTML 还指向旧哈希，旧用户正常但新用户拿不到旧文件。回滚同理，必须整目录回退（见第 10 节）。

## 5. 安全响应头建议

CSP 可直接用下面这版（本项目无外链、无 eval、无 `data:` CSS，实测 `dist/assets/*.js` 不含 `eval(`、CSS 不含 `url(data:`）：

```
Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self'; connect-src 'self'; form-action 'self'; frame-ancestors 'none'; base-uri 'none'; object-src 'none'
X-Content-Type-Options: nosniff
Referrer-Policy: no-referrer
Permissions-Policy: geolocation=(), camera=(), microphone=(), payment=(), usb=()
X-Frame-Options: DENY
```

说明与取舍：

- `style-src` 里的 `'unsafe-inline'` 是为了 `404.html` 的内联 `<style>` 与 Vue 的 `:style` 绑定；若要彻底去掉，可把 404 页的内联样式改为独立 CSS 并加 `sha256-` 哈希，再收窄为 `style-src 'self'`。
- `frame-ancestors 'none'` + `X-Frame-Options: DENY` 双写，兼容老浏览器。
- 本项目**不需要**任何 `connect-src` 外部域（无接口调用）。将来若接入后端，必须逐项放开而不是整体 `*`。
- 若平台不支持自定义头（如部分对象存储静态网站模式），至少保证 `X-Content-Type-Options: nosniff` 与正确 MIME。

## 6. 404 配置

`404.html` 必须以 **HTTP 404** 状态码返回，不能以 200 返回（否则搜索引擎与监控都会把它当正常页）。

- Nginx：`error_page 404 /404.html;` + `location = /404.html { internal; }`
- Caddy：`handle_errors { rewrite * /404.html; file_server }`
- Netlify（`netlify.toml`）：`[[redirects]] from = "/*" to = "/404.html" status = 404`
- Cloudflare Pages / Vercel：根目录放 `404.html` 即自动生效
- 腾讯云 COS / CDN / EdgeOne：在「错误文档 / 自定义错误页」中配置 `404.html`，状态码保持 404

**不要**配置「所有未匹配路径重写到 `/index.html`」这类 SPA 兜底：本项目没有前端路由，兜底会让任意错误路径返回 200 的应用外壳（软 404），`404.html` 永远不会出现，也让第 4 节的缓存策略失效。

## 7. robots.txt 与 noindex 的关系

- `robots.txt`：`User-agent: *` + `Disallow: /` —— 请求层面的「别抓」，靠爬虫自愿遵守，恶意/部分爬虫会无视。
- `noindex,nofollow`：写在三个 HTML 的 `<meta name="robots">` 里 —— 收录层面的「别存」，即使页面被抓到也不会进索引。
- 两者是**互补而非替代**：一个是入口闸门，一个是内容标记。本原型两个都上。
- 现状核对：`dist/index.html`、`dist/community.html`、`dist/404.html` 均含 `noindex,nofollow`；`dist/robots.txt` 含 `Disallow: /`。为避免被收录，本项目**不提供** `sitemap.xml`（没有可提交的公开页面），也不需要 canonical/hreflang/结构化数据 —— 这些是「求收录」的技术项，本项目目标相反。

## 8. 限制：只适配根路径部署

`dist/index.html` / `dist/community.html` 里的引用是根路径绝对写法（`/assets/intake-*.js`、`/favicon.svg` 等，共 7 个唯一引用）。这意味着：

- ✅ 部署在 `https://example.com/` 正常。
- ❌ 部署在 `https://example.com/app/` 会全盘 404（HTML 里的 `/assets/...` 会去域名根找）。

要支持子路径，需要在 `vite.config.ts` 里设 `base: '/app/'` 并重新构建（本次任务边界内不改构建配置，故未做）。同理，`404.html` 里的 `href="/"`、`href="/community.html"` 也是根路径；但该页样式与脚本内联，所以即便子路径部署，404 页自身不会「样式全丢」。

## 9. G3 阻塞项：公开发布前必须先解决（本说明不覆盖）

以下任一项未关闭，**都不得把这个站点放到公开可访问的地址上**：

1. **跨浏览器实机验证** —— 目前验证集中在 Chromium 系；Safari/iOS、Firefox、旧版 Edge 的表现与 `localStorage` 配额/隐私模式行为未闭环。
2. **真机读屏器** —— VoiceOver / TalkBack / NVDA 真机走查未完成；静态审计（`audit-a11y`/`audit-ui`）不等价于真实读屏体验。
3. **真实 PII** —— 当前只含合成数据。一旦输入真实姓名/电话/住址/健康信息，本项目的「纯 localStorage、无审计日志、无加密、无权限模型」形态即为不合格，需重新做数据合规评估。
4. **访问控制** —— 无登录、无鉴权。静态托管下任何人都能访问站点；若面向内部人员使用，必须在外围加访问控制（如平台级 Access、IP 白名单、或统一身份网关），否则等同于公开。
5. **运营与备案** —— 中国大陆公网发布需 ICP 备案/主体资质（域名 + 服务器/托管均在境内时）；对外传播口径、免责声明、演练数据说明需业务方确认。
6. 其他无服务端带来的固有限制：无审计、无多人协作真同步、无数据备份、无服务端校验（客户端校验可被绕过）。

因此本次结论只能是：**静态可部署性就绪，公开上线未就绪。**

## 10. 回滚

回滚的最小单位是「整版产物目录」，不是单个文件。

1. **发布前留底**（推荐，最简单）
   ```bash
   # 发布前把当前线上产物留一份
   cp -r dist "dist.prev-$(date +%Y%m%d-%H%M)"
   ```
2. **回滚**：把上一版目录整体覆盖回站点根（不是只替换 HTML）。若平台支持部署历史（Cloudflare Pages / Netlify / Vercel 都有），直接用「Rollback to this deployment」更安全，能保证 HTML 与 assets 同一版本。
3. **按哈希回退的坑**：`assets/` 文件名含内容哈希，只回退 HTML 而不回退 assets 会出现「HTML 指向不存在的旧 chunk → 白屏」。所以要么整目录回退，要么保留至少 1–2 个历史版本的 `assets/` 不删。
4. **回滚后必须复核**：`node tools/check-deployability.mjs --base=<线上地址>`，并把浏览器强刷（HTML 是 `no-cache`，一般无需清缓存）。
5. 域名/DNS 层面本次未做任何变更，因此回滚不涉及 DNS。

```
E 404 页具备 noindex 与两条返回路径 …… PASS
F 预览服务四个路径均返回 200 …… PASS（/、/community.html、/robots.txt text/plain、/404.html）
合计：6/6 PASS，0 FAIL
```

`check-deployability.mjs` 的判定边界，说清楚以免误读：

- 它只验证**产物与预览可达性**，不验证跨浏览器、读屏器、真实数据合规、访问控制。
- F 项判 200；若某路径返回 200 但内容是应用外壳（回退），脚本会额外打印 `[NOTE]` 提示「文件没真被提供」，此时不要只看 PASS。
- 脚本不启动/不关闭服务，`--base` 默认 `http://127.0.0.1:5180`；换线上地址即可复用做发布后冒烟。
