# A+ 端组件拆分（2026-10-23）

## 1. 结论

`src/App.vue` 从 **1,923 行** 降到 **88 行**，A+ 端拆为「1 个状态源 + 3 个支撑模块 + 22 个组件」。
拆分不改任何界面与交互：11 个固定状态的规范化 `outerHTML` 逐字节一致，7 张视觉基线截图哈希不变，
14 个门禁脚本仍为 **119/119**。

## 2. 先做的调研

| 来源 | 提炼要点 | 落地位置 |
| --- | --- | --- |
| W3C WAI-ARIA APG《Dialog (Modal) Pattern》 | 打开时焦点进入对话框；Tab/Shift+Tab 在内部循环；Esc 关闭；关闭后焦点归还触发元素；`aria-modal` 只在真正阻止背景交互时才标记 | `dialog-focus.ts` |
| Vue 官方文档《Composables》 | 具名 `use*`；返回「普通对象 + ref」而非 `reactive()`，解构后仍保持响应性；按「逻辑关注点」拆分是官方认可的提取动机 | `workbench.ts` / `context.ts` |
| `focus-trap/tabbable` README | tabbable 需排除负 tabindex、disabled、`display:none`、`visibility:hidden`、未挂载与 inert 容器；正 tabindex 应按序前置（本项目无正 tabindex） | `dialog-focus.ts` 的 `focusables()` |
| `KittyGiraudel/a11y-dialog` | 对话框生命周期与背景惰性化分离；样式不侵入（unopinionated），便于保留既有设计系统 | 背景仍用 `:inert`，不改样式 |

结论：**不引入依赖**。`tabbable`、`a11y-dialog` 的能力在本项目只需约 60 行，离线环境也无法安装；
按官方文档实现即可，且行为与既有门禁断言完全兼容。

## 4. 关键决策与取舍

**为什么用 provide/inject 而不是 props。**
A+ 端的详情面板要用到 30 余个绑定；逐层透传会产生大量只做转发的 props，任何新增字段都要改三层。
现在 `App.vue` 调用一次 `useAplusWorkbench()`，子组件 `useAplusContext()` 解构所需字段：
状态仍是 ref/computed（解构不丢响应性），动作是函数，不存在第二份副本。
代价是子组件不能在上下文之外单独渲染——因此 `context.ts` 在缺失 provide 时抛出可定位的错误，而不是静默降级。

**为什么状态集中在一个 composable，而不是拆成五个。**
`resetAllForms()`、`closeAllDialogs()` 与各提交动作互相调用（关闭弹层要复位全部表单，投诉也要跟着复位）。
强行按「社区桥 / 备份 / 投诉」切片会把调用关系变成回调注入，可读性反而下降。
折中是：**纯函数一律下沉**（`presentation.ts`，已被单测覆盖），**与 Vue 生命周期耦合的状态集中**（`workbench.ts` 用分组注释定位）。

**为什么样式几乎不用改。**
入口的 `<style scoped>` 只有 3 条规则，逐条核对后确认：
`.intake-gate .button { flex: none }` 与 `.button:disabled:hover` 已被全局规则覆盖（`.button:active:not(:disabled)` 已做守卫），
只有 `.mobile-nav button:disabled { opacity: .5 }` 确实依赖 scoped，补进 `src/style.css` 即可。

**为什么不用 `<Teleport>`。**
弹层本来就渲染在 `.app-shell` 末尾，层级与滚动容器都正确；加 Teleport 会改变 DOM 位置，
影响 `document.querySelector('.modal-backdrop .modal')` 这一既有焦点查询，收益为零。

## 5. 等价性验证

拆分重构最怕「看不出来但已经变了」。除常规门禁外，新增一道结构化比对：

1. `tools/snapshot-dom.mjs` 在构建产物上依次进入 11 个固定状态
   （默认队列、待分诊筛选、新建/流转/检查点/投诉/高风险/社区桥/帮助弹层、投诉选中、角色切换），
   抓取 `.app-shell` 的 `outerHTML`，去掉 `data-v-*` 与 toast 临时文案后压平空白。
2. 拆分前后各跑一次，逐状态比较字符串。

结果：**11/11 完全一致**（含长度与内容）。

## 7. 复现命令

```bash
npm run build
npm run preview -- --port 5180 --host 127.0.0.1 --strictPort
node tools/snapshot-dom.mjs --base=http://127.0.0.1:5180 --out=dom-a.json
# 改动后重新构建，再抓一次并比较 name/html 字段
npm run test:unit
```

`snapshot-dom.mjs` 的快照含时间文案，只用于「同一份数据、两次构建」的即时对比，不作为长期基线；
长期基线仍是 `tools/visual-baseline/` 的截图哈希。
