# 首页公告轮播：可访问性、手势与降级（2026-10-23）

## 1. 交付摘要

B 社区入口首页新增「邻里公告板」轮播，落实功能说明中的 Banner 区（社区公告、时间银行规则、志愿活动招募、养老科普、独居老人安全注意五类内容）。

- 新增 `src/community/banner-slides.ts`（数据 + 纯逻辑）与 `src/community/components/HomeBanner.vue`（视图 + 状态机）。
- 支持自动轮播、前后切换、圆点直达、方向键、Pointer 滑动、播放/暂停；移动端与桌面共用一套 DOM。
- 无障碍按 W3C APG Carousel 模式实现：`region` + `aria-roledescription="carousel"`、幻灯片 `tabpanel` + `slide`、圆点 `tablist`、自动播放时 `aria-live="off"`、停止后转 `polite`。
- 尊重 `prefers-reduced-motion`：默认不自动播放，显式点「播放」仍可覆盖；过渡时长由全局规则压到 0.01ms。
- 专项回归 `tools/check-home-banner.mjs` **24/24**；单测 61 → **72**；视觉基线 7 → **8** 个状态。
- 未新增依赖，未引入外部字体/图片/请求。

## 2. 调研与取舍

| 来源 | 可借鉴要点 | 本次处理 |
| --- | --- | --- |
| [W3C APG Carousel 模式](https://www.w3.org/WAI/ARIA/apg/patterns/carousel/) | 必须有停止/开始轮播的按钮；焦点进入即停止且**不自动恢复**；悬停暂停；圆点可用 Tabs 模式；`aria-live` 随轮播状态切换 | 全部采用；焦点进入后把 `autoRotate` 置 false，只有点「播放」才恢复 |
| [APG 自动轮播示例](https://www.w3.org/TR/2021/NOTE-wai-aria-practices-1.2-20211129/examples/carousel/carousel-1-prev-next.html) | 自动播放时实时区为 `off`，停止后为 `polite`；旋转控制排在内容之前；幻灯片用位置名称 | 采用：区域标题、控制顺序、`第 N 张，共 5 张` |
| [bluecadet/embla-carousel-a11y](https://github.com/bluecadet/embla-carousel-a11y) | `region`/`carousel`、`group`/`slide`、非当前幻灯片 `aria-hidden`、独立实时区、开发期告警 | 采用角色与隐藏策略；实时区按 APG 放在幻灯片容器上，不另建隐藏节点 |
| [nwidynski/embla-carousel-aria](https://github.com/nwidynski/embla-carousel-aria) | 圆点用 Tabs 时幻灯片改用 `tabpanel`；自动滚动时建议关闭播报 | 采用 `tabpanel`；`aria-live` 在播放中为 `off` |
| [Embla Autoplay 文档](https://www.embla-carousel.com/docs/v8/plugins/autoplay) | `stopOnFocusIn` 默认 true、`stopOnInteraction` 默认 true、`stopOnMouseEnter` 默认 false | 采用前两项语义；悬停暂停改为只作用于幻灯片区域，避免鼠标停在控制条上时无法恢复 |
| [Vue APG 复刻示例](https://masup9.github.io/apg-patterns-examples/patterns/carousel/vue) | Tabs 选择器、`aria-controls`、roving tabindex | 采用结构与键盘契约，复用项目已有的 `v-tablist` 指令 |

**分歧处理（以文档为准）**：Embla 的 `stopOnFocusIn` 在 `stopOnInteraction: false` 时会在失焦后恢复轮播，Vue 复刻示例也写了「焦点离开后恢复」。APG 模式明确要求「焦点进入后停止，除非用户主动请求，否则不重启」。本次实现遵循 APG：**失焦不恢复**，必须点「播放」。

**不引第三方库的原因**：项目离线交付、禁止 `npm install`；只需要单张淡入淡出，不需要拖拽物理、无限循环与响应式断点。自实现把实时区、暂停条件、焦点交接集中在约 300 行组件内，且纯逻辑可被 Node 单测覆盖。

## 3. 设计与交互

### 3.1 信息结构

首页顺序调整为：问候 → 我的待办 → **邻里公告板** → 品牌 Hero → 邻里新鲜事 → 快捷入口 → 搜索 → 社区一览 → 安全提示。公告属于时效信息，放在 Hero 之前，移动端无需滚动即可看到第一条。

五条内容全部为合成文案，`meta` 行固定标注边界（社区公告 / 规则 / 招募 / 科普 / 安全提示），不出现电话、链接、真实机构名。

### 3.2 视觉

- 容器沿用令牌：`--surface`、`--line`、`--r-lg`、`--shadow-sm`；左侧 5px 色条按内容切换 green / sand / clay / blue 四种色调，背景用同色系径向渐变。
- 高度：桌面约 205px，390px 约 236px；控制条 44px，圆点 44px 触控高度，桌面 CTA 36px、移动端 44px。
- 幻灯片用 CSS Grid 同一单元格堆叠，容器高度取最高一张，切换时**不产生页面回流**；非当前页用 `visibility: hidden`，不参与绘制。
- 正文对比度 ≥4.5:1；圆点非文本对比度按 3:1 选取（`#7f8c7b`），选中态使用当前色调。
- `forced-colors: active` 下补边框与 `Highlight` 选中色。

### 3.3 状态机

```
autoRotate（用户意图，默认 !prefers-reduced-motion）
  ├─ false：手动切换 / 焦点进入 / 点暂停 / 系统切到减少动态
  └─ true ：点播放（唯一恢复入口）
hovering（仅幻灯片区域）      → 临时暂停，移出恢复
pageHidden（visibilitychange）→ 临时暂停
rotationAllowed = autoRotate && !hovering && !pageHidden
```

- 自动播放间隔 7s；`aria-live` 在允许轮播时为 `off`，否则 `polite`。
- **焦点与点击的时序**：鼠标点按钮会先 `focusin` 再 `click`。如果 `focusin` 一律停播，点「暂停」会先停再被 click 打开，语义反转。组件用 Pointer 意图标记跳过由鼠标按下引发的 `focusin`；键盘 Tab 进入仍会停播。
- **焦点交接**：方向键在幻灯片内切换时，原幻灯片会变成 `inert`，焦点会掉到 `body`。`goTo()` 检测焦点是否在幻灯片内，若是则在新幻灯片渲染后把焦点交给它的主操作按钮，键盘可继续操作。
- **悬停范围**：只监听幻灯片视口，不监听整个卡片。否则鼠标停在「播放」按钮上时 `hovering` 恒为 true，点了播放也不转。

### 3.4 手势与键盘

- Pointer 滑动阈值 40px；`|dy| > |dx|` 时判定为纵向滚动，不切页；`touch-action: pan-y` 保留页面滚动。
- 滑动结束后 400ms 内拦截一次合成 `click`，避免「滑完顺手触发按钮」；`pointercancel` 清理状态。
- 方向键 ←/→ 在非圆点区域切换；圆点内交给 `v-tablist` 的 roving tabindex 与 Home/End，避免一次按键切两张。
- 旋转控制是容器内第一个可聚焦元素，符合 APG 的 Tab 顺序要求。

### 3.5 无障碍细节

- 容器：`role="region" aria-roledescription="carousel" aria-labelledby="home-banner-title"`，标题文本为「邻里公告板 · 本机演练」。
- 幻灯片：`role="tabpanel" aria-roledescription="slide" aria-label="第 N 张，共 5 张"`；非当前页 `aria-hidden="true"` + `inert` + `visibility:hidden` 三重隐藏。
- 圆点：`role="tab"`、`aria-controls` 指向幻灯片、`aria-selected`、`tabindex` 由 `v-tablist` 维护；可访问名包含序号、分类与标题。
- 播放按钮：可访问名随状态在「暂停自动播放 / 播放自动播放」之间切换；不加 `aria-pressed`，避免与「暂停」语义冲突。
- 计数 `01 / 05` 为装饰信息，`aria-hidden`；位置由幻灯片名称与圆点名称播报。

回归过程中发现并修复了三个真实问题：

1. 方向键切换后原幻灯片变 `inert`，焦点掉到 `body`，后续方向键失效 → 增加焦点交接（HB10 由失败转通过）。
2. 首次实现把「暂停自动播放」的点击语义与 `focusin` 停播混在一起，点暂停会变成继续播放 → 拆分用户意图与临时暂停，并用 Pointer 意图标记区分鼠标与键盘。
3. 在 `pointerdown` 立即 `setPointerCapture` 会把后续 `click` 的目标重定向到视口，幻灯片里的 CTA 用真实鼠标点不动（合成 `.click()` 测不出来） → 改为横向拖动超过 40px 后才捕获；专项增加真实鼠标点击与拖动断言（HB15 / HB15b）。

## 6. 已知限制

- 视觉基线依赖**同一台机器、同一 Chrome 版本**（本次 Chrome 156）；换机或升级浏览器需人工核对后 `--update`。
- 滑动手势由合成的 `PointerEvent` 驱动，尚未在真实触屏设备上人工验收；iOS Safari 的边缘返回手势也未覆盖。
- 读屏器（NVDA / VoiceOver / 讲述人）未做人工走查；实时区行为按 APG 实现，但实际播报顺序需真人确认。
- 播放/暂停状态不持久化，刷新后回到默认；这是刻意选择，避免「上次暂停导致这次以为坏了」。
- 轮播高度由最高一张决定，摘要单测限制 ≤60 字；若未来文案变长，需要重新评估首屏高度。
- 公告为静态数据，不接后台、不做定向推送；「查看志愿活动」等入口只切换到本机页签，不产生真实报名。
