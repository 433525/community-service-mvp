# B 受控社区实施范围

日期：2026-10-21。依据：用户最新截图和“按照方案B来做”。附件中的功能说明为产品参考，截图确定本轮控制边界。

## 决定与当前范围

项目场景已由用户确认：学校大创项目，用户本人为项目负责人。继续以主要功能可用为优先；具体学校、指导老师、首批使用对象及受理/审核分工后续补充。

立即开发 B 本地合成原型，不等待真实 A+ 组织确定。保留 Vue 3 + Vite + Vant、双入口与本机存储，优先完成主要功能。既有 A+ 受理和跟进继续可用。此处 B 不是历史 B1–B6 的全部范围。

| 能力 | 本轮实现 |
|---|---|
| 社区范围 | 访客/成员/审核员的虚构身份演练，社区正文对访客不展示 |
| 信息流 | 仅审核通过且公开的帖子，保留搜索、类型筛选 |
| 发布/评论 | 待审→通过/驳回，通过内容可下架，记录理由；审核不改写正文 |
| 旧存档 | 缺审核状态归待审，不自动公开旧内容 |
| 接单/报名 | 成员只对已公开且审核通过内容操作；只有“活动招募”可报名，可取消报名；志愿记录不提供报名 |
| 求助履约 | 本机演练状态机：待接单→已接单→待确认完成→已完成；另有取消/关闭、争议及撤销/关闭争议；每步写入订单事件时间线；为演示双人流程提供明确标注的“合成对方”代记录按钮 |
| 时长记录 | 订单完成生成一条“未结算”演示时长；不结算、不兑换、不提现，不代表真实双方确认 |
| 系统通知 | 本人内容审核结果、合成对方订单动作、本人订单留言被下架等本机事件写入系统通知；不投递外部 |
| 沟通 | 关闭自由私聊，仅本人参与、进行中且公开审核通过的求助可留言，无自动回复；完成/关闭后只读 |
| 举报 | 帖子/评论/订单留言→待处理→已处理或不予支持，保存处理理由 |
| 内容管理 | 审核员查看原文、下架帖子/评论/订单留言，保留原内容与操作日志 |
| 本机存档 | 显示存档状态、坏档保护、多标签冲突检测；“我的”提供本机存档 JSON 只读快照与复制，不提供导入或上传 |
| 受理衔接 | 只将审核通过求助导入 A+ 本机队列；订单状态仅展示，不自动派单或联系居民 |

“已处理”只表示演练审核员已记录处理结论，不表示举报成立或内容自动下架。必要时先执行下架，再记录举报结论。

## 上线前仍需完成

1. 项目负责人已确定为用户本人；补充实际使用对象、运营主体、服务范围和受理/审核分工。学校大创项目背景不自动等于学校承担运营主体职责。
2. 根据实际主体、渠道和功能核实注册、备案与小程序类目要求。截图提出个体工商户/企业及非经营性备案设想，尚未形成适用性结论或完成办理。
3. 建立真实服务端登录、邀请码/社区成员核验、审核员授权、社区隔离；不得将本机身份选择器用于真实权限控制。
4. API、数据库、服务端逐项权限校验、备份恢复、审计与数据留存/纠错/删除机制。
5. 形成发布规则、审核时限与值守、举报申诉、违规处置、紧急情况人工转介制度；确定谁接收、谁复核。
6. 用已确定范围完成正式验收，取得真实运营决定后再部署开放；当前无真实账号、居民数据、履约、消息投递或收费结算。

## 交付与验证边界

DeepSeek 负责状态、数据校验和持久化协作；Codex 负责界面与集成审阅。已有构建、静态核对和部分本机主流程操作证据，详见运营准备目录中的 B 主流程及评论审核记录；不将编译通过或局部操作表述为全部业务验收通过。代码存放于项目私有仓库；不上传合成运行存档、密钥、全局配置或依赖目录。新增开发参考及后续任务见 [补充开发文档对照与实施清单](补充开发文档对照与实施清单.md)。
