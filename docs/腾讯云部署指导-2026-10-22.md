# 腾讯云部署指导（静态演示版）· 2026-10-22

> 这份文档是操作指导，不是部署确认。没有创建云资源、上传文件、绑定域名、修改 DNS 或申请/安装证书；仍需你自行决定并执行。仅使用合成演练数据。

## 1. 先确认项目是什么

当前仓库是 Vue/Vite 构建的**纯静态双入口原型**：`/` 与 `/community.html`。构建后的 `dist/` 可由 Nginx 或 COS 提供文件，不需要常驻 Node 服务；没有 API、服务端身份认证、数据库或权限校验。演练身份选择器不是登录，数据保存在当前浏览器 `localStorage`，按域名/协议/端口隔离。

因此：把 `dist/` 放到 Lighthouse 服务器上，只解决静态文件托管；不会让演示身份成为真实权限，也不能关闭公开发布门禁 G3。当前 G3 仍是 FAIL，不得把原型称为可公开运营系统。

## 2. 选哪条路

| 目标 | 建议 | 关键边界 |
| --- | --- | --- |
| 需要一台“服务器”练习 SSH、Nginx、部署和回滚 | 腾讯云轻量应用服务器 Lighthouse + Nginx | 服务器只托管静态文件；没有后端鉴权。 |
| 只想托管 `dist/`，不需要登录服务器 | COS 静态网站托管 | COS 不运行服务端代码；公开读权限、域名与 HTTPS 要谨慎配置。2024-01-01 后新建桶的默认域名有静态预览限制，通常需要自定义域名。见腾讯云文档 [1]。 |
| 要真正对居民开放并有账号/权限 | 先设计后端、服务端鉴权、数据治理和运营流程，再选 CVM/Lighthouse/托管后端 | 不是把当前 Vite 产物上传就能完成；不要接入真实个人信息。 |

若主要演示对象在香港，可先比较腾讯云香港地域的可用规格与网络；若计划面向中国内地并把域名指向内地资源，须先核实并完成 ICP 备案等要求。腾讯云说明香港服务器开办网站/APP 不需 ICP 备案；内地服务器则须先备案。该结论不替代其他法律、学校或运营审批，详见 [4]。

## 3. 路线 A：Lighthouse + Nginx（按“服务器”需求）

### 3.1 创建实例前

1. 在腾讯云控制台确认账号、计费、可用地域、实例规格、系统镜像和公网带宽；价格/可售地域以购买页为准。本指导不会替你下单。
2. 选一个可维护的 Linux 系统镜像（例如控制台当前提供的 Ubuntu LTS 系统镜像），记下实例公网 IP。使用系统镜像需自行安装 Nginx。
3. 先规划访问范围：演示期间尽量限制到校内网络、VPN 或指定来源 IP；这只是网络层限制，不等于应用登录。
4. Lighthouse 防火墙按最小权限配置：SSH TCP 22 只允许你的管理来源 IP；需要 HTTP 时开放 TCP 80，需要 HTTPS 时开放 TCP 443。不要把 SSH 长期开放给 `0.0.0.0/0`。防火墙控制入站流量，规则详见 [2]；HTTPS 访问也要确认 443 可达 [6]。

### 3.2 本地构建并传文件

在项目目录的 Windows PowerShell 中运行：

```powershell
npm ci
npm run build
```

确认生成 `dist/` 后，只上传 **`dist/` 目录里的全部内容**，不要只上传 `dist` 这一层。先通过腾讯云控制台/SSH 以密钥登录。Ubuntu 镜像常用账户名为 `ubuntu`，具体以实例详情页为准；不要把密码、私钥贴到聊天或写进项目文件。腾讯云的 Linux 登录与账户说明见 Lighthouse 文档 [3]。

示例（占位符需由你自己替换；以下命令不应原样粘贴占位符）：

```powershell
ssh ubuntu@<实例公网IP> "sudo install -d -o ubuntu -g ubuntu /var/www/a-plus-app"
scp -r .\dist\* ubuntu@<实例公网IP>:/var/www/a-plus-app/
```

### 3.3 配置 Nginx 静态站点

在实例上创建一个 Nginx 站点配置，`root` 指向 `/var/www/a-plus-app`。本项目是两个真实 HTML 入口，不需要 SPA catch-all；仅把存在的文件交给 Nginx，未知路径应返回 404。示例：

```nginx
server {
    listen 80;
    server_name _;
    root /var/www/a-plus-app;
    index index.html;

    location /assets/ {
        try_files $uri =404;
        expires 1y;
        add_header Cache-Control "public, immutable";
    }

    location ~* \.(?:html|txt|svg)$ {
        expires -1;
        add_header Cache-Control "no-cache";
    }

    location / {
        try_files $uri $uri/ =404;
    }

    error_page 404 /404.html;
}
```

注意：如果系统自带的默认站点也声明了 `default_server`，先检查并调整配置，避免两个默认站点冲突；保留原文件备份。HTML 与根目录 SVG/robots 不做长缓存，`/assets/` 内的文件名带内容哈希，才适合长期 immutable 缓存。不要直接加未经验证的严格 CSP；当前项目的响应头/CSP 仍需单独验收。

检查并重载：

```bash
sudo nginx -t
sudo systemctl reload nginx
```

### 3.4 验证路径和回滚

从你的电脑检查以下路径（用实例 IP 临时验收，不需要先改 DNS）：

- `http://<实例公网IP>/`：A+ 入口。
- `http://<实例公网IP>/community.html`：社区入口。
- `/robots.txt`：仍为 Disallow。
- `/404.html`：兜底页本身可访问。
- `/this-path-should-not-exist`：应返回 HTTP **404**，并显示 404 兜底页，而不是 200 的应用外壳。

也可用 `curl.exe -I http://<实例公网IP>/community.html` 查看响应头。更新时保留上一版 `dist` 备份；上传新版本后复查两入口、资源加载、缓存与 404。若失败，恢复上一版整套文件并重载 Nginx。

### 3.5 HTTPS 与域名（需你另行决定）

只有在你明确拥有并授权使用某个域名后，才继续做域名解析/绑定。申请或上传证书后按腾讯云 Lighthouse 的 Nginx 证书步骤安装，并确认防火墙 443 已开放；官方说明见 [5]。域名和 DNS 操作本指南不代办，也没有发生。HTTP→HTTPS 跳转应在证书可用并实测后再开启。

## 4. 路线 B：COS 静态网站（不买 VM）

1. 创建 COS bucket 后上传 `dist/` 的**内容**，不是外层目录；开启“静态网站”，索引文档填 `index.html`，错误文档填 `404.html`。
2. 只要文件公开可读，任何能够访问该站点的人都可能下载静态资源；COS 静态托管没有服务端登录/权限。先确认公开范围与演示数据，再设置访问权限。
3. 腾讯云 COS 支持 HTML/客户端脚本的静态托管，不支持执行 PHP、JSP 等服务端脚本；2024-01-01 后创建的 bucket 通过默认域名访问静态页面受到限制，常需配置自定义域名。自定义域名、CNAME/DNS 和 HTTPS 需按腾讯云文档 [1]、[7] 由你授权后操作。
4. 本项目要求站点根路径部署；两个入口是 `/` 与 `/community.html`。不要放在 `/app/` 子路径，否则根路径资源引用会失效。

## 5. 公开发布前仍未通过的事项

- 当前 `dist/` 仍是无后端原型。访客/成员/审核员切换只是演示状态，不是账号体系；任何人都可能下载前端资源。
- 要公开提供真实服务，仍需运营主体与合规决策、真实账号与服务端授权、PII 数据治理、审核值守/举报申诉与紧急转介、跨浏览器/读屏器等验证。
- 现有存档是浏览器本地 `localStorage`，换 origin 不会同步数据；切换域名、HTTP/HTTPS 或端口会看到另一份本地数据。
- Gate G3 当前 **FAIL**。本机 `check-deployability` 通过只代表静态产物结构检查通过，不等于线上部署已验收或公开发布已获准。
