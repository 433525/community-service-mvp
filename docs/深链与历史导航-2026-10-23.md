# 深链与历史导航（2026-10-23）

本轮把页签与选中记录写进 URL，解决交接文档 §7 的已知问题 #7：“无 URL 路由/页签状态，刷新回首页，帖子深链不写 URL”。仍然不引入依赖、不改变存储结构、不触碰合成数据边界。

## 1. 目标与边界

| 项目 | 本轮处理 |
|---|---|
| B 社区入口 | `?tab=` 直达六个页签；`?post=` 直达并聚焦帖子；刷新还原；前进/后退可用 |
| A+ 工作台 | `?case=` 直达登记记录；队列选择同步地址；失效参数回收 |
| 分享 | 帖子与记录详情提供“复制链接”，只包含页签与记录 id |
| 无障碍 | 页签切换写入 polite 状态区播报；后退时焦点回到主内容；标题随页签更新 |
| 不做 | 服务端路由/SSR、登录态入 URL、搜索词/筛选入 URL、真实部署 |

搜索与筛选仍只在本页内存：它们随输入高频变化，写入 URL 会产生大量历史记录，也容易把内部筛选口径带进分享链接。

按要求先查同类实现，再落代码。结论以官方文档为准。

| 来源 | 可借鉴要点 | 本项目取舍 |
|---|---|---|
| [Vue 官方 Routing 指南](https://vuejs.org/guide/scaling-up/routing) | 简单场景可直接用 `hashchange`/History API，不必引入 vue-router；示例明确要求事件监听可清理 | 采用无依赖方案；`onRoutePop()` 返回解绑函数，`onBeforeUnmount` 调用 |
| [onmax/nuxt-skills：Simple Hash Routing Requires Event Listener Cleanup](https://github.com/onmax/nuxt-skills/blob/main/skills/vue-router-best-practices/reference/router-simple-routing-cleanup.md) | 匿名监听器无法移除，组件重建后会重复响应并泄漏内存 | 监听器保存引用并统一解绑；两入口各自只注册一次 |
| [Makio64/vue-tiny-router](https://github.com/Makio64/vue-tiny-router) | 约 1.33 kB，`useRoute`/`useRouter` 组合式 API；自动拦截站内链接；不解析查询串 | 借鉴组合式读写与默认值省略；不引入依赖，也不需要链接拦截（页签按钮已集中调用同一函数） |
| [booploops/pod-router](https://github.com/booploops/pod-router) | 组件级路由，hash/history/memory 三种模式，明确面向页签界面 | 证明页签场景无需全局 router；其“路由组件”模型对本项目过重 |
| [MDN：History.pushState()](https://developer.mozilla.org/en-US/docs/Web/API/History/pushState) | 目标 URL 必须同源；`pushState` 不触发 `popstate`；不传 URL 时保持当前地址 | 只用查询串更新，同源校验交给 `URL`；`writeRoute` 在地址未变时不写历史 |
| [MDN：popstate 事件](https://developer.mozilla.org/en-US/docs/Web/API/Window/popstate_event) | 仅在浏览器前进/后退（或 `history.back()`）时触发，触发时 `location` 已更新；页面未被交互时可能不触发 | 处理器只读当前 URL，不依赖 `event.state`；用查询串签名忽略页内锚点后退 |
| [Accessible SPA route changes](https://www.accessible-data-interfaces.com/core-aria-keyboard-navigation-for-data-uis/focus-management-in-single-page-apps/managing-route-change-focus-in-angular-and-vue) | 路由变化后：更新标题、polite 状态区播报、焦点移入新内容；查询参数只改筛选时不应重置焦点 | B 入口三者齐全；后退时聚焦 `#community-main`；纯筛选变化不写 URL、不移动焦点 |

**为什么用查询串而不是 hash**：B 的消息页与审核页已有 `#messages-notices`、`#moderation-posts` 等分区锚点（原生跳转、可分享）。若路由也占用 hash，点击分区会把路由覆盖成 `#messages-notices`，刷新即丢失页签。查询串与锚点互不干扰；本轮专门用 DL8b 锁定该行为。

## 3. 实现

### 3.1 共享模块

- `src/shared/route-state.ts`
  - `readRouteParam(name)`：缺失/解码失败返回空串，调用方无需判空。
  - `writeRoute(values, { replace, clearHash })`：空值删除键；地址未变不写历史；`try/catch` 吞掉 `file://`、沙箱 iframe 与历史配额异常，界面状态不回滚。
  - `onRoutePop(handler)`：只监听 `popstate`，返回解绑函数。
  - `routeSignature()`：当前查询串签名，用于忽略无关的 `popstate`（例如页内锚点后退）。
  - `buildShareUrl(values)`：以当前页面为基准，清空查询串与 hash，只写允许分享的键。
- `src/shared/clipboard.ts`
  - 安全上下文优先 `navigator.clipboard.writeText`；否则退回只读文本域 + `execCommand('copy')`。
  - 降级路径复制后移除文本域，并把焦点还给原控件；失败返回 `false`，由调用方提示手动复制。

### 3.2 B 社区入口（`src/community/App.vue`）

- 初始化：`?tab=` 合法则直达；只有 `?post=` 时推断为社区页；两者都无则首页，地址保持干净。
- 页签切换：`pushState` 写入 `?tab=`，清空 `post` 与失效锚点；同时播报“已切换到 ×× 页”。
- 帖子深链：`?tab=community&post=<id>`，由 `CommunityView` 聚焦卡片并高亮 4 秒；找不到时发出 `focusMissing`，上层提示“不存在、未通过审核或已下架”并 `replaceState` 清掉参数。
- 后退/前进：`popstate` → 重新解析页签；页签变化时回到顶部、聚焦主内容并播报。
- 复制链接：帖子操作区新增“复制链接”，生成 `community.html?tab=community&post=<id>`。

### 3.3 A+ 工作台（`src/App.vue`）

- `?case=<id>` 在挂载后应用；记录存在则选中，不存在则提示“链接中的演练记录不存在，已显示队列首条”并清理参数。
- 队列点击与关联记录跳转使用 `replaceState` 同步 `case`：地址始终指向当前详情，但不会让“后退”逐条回放记录（工作台语义）。
- 详情头部新增“复制链接”，生成 `/?case=<id>`。

### 3.4 URL 约定

| 参数 | 取值 | 默认行为 |
|---|---|---|
| `tab` | `home` / `community` / `publish` / `messages` / `profile` / `moderation` | 首页省略 |
| `post` | 帖子 id（`SYNTH-POST-*`） | 省略；仅在与 `tab=community` 同时出现或单独出现时生效 |
| `filter` | `help` / `volunteer` / `neighbor` | 省略（`all`）；仅社区页生效，未知值在首次加载时清除 |
| `case` | 记录 id（`SYNTH-*`） | 省略 |

其他查询参数原样保留（不主动删除外部参数），但复制链接只保留上表键。`filter` 用 `replaceState` 更新，点选筛选不会堆积历史记录。

## 5. 已知限制

1. 深链只在客户端生效；静态托管需保证 `/` 与 `/community.html` 可访问（已验证），没有 SSR/预渲染。
2. `?tab=` 不包含搜索词、演练身份和“只看待接单”；`filter` 只覆盖四类动态筛选。分享链接的接收者仍需自行切换为合成成员身份。
3. A+ 记录选择与 B 筛选切换使用 `replaceState`，浏览器“后退”不会逐条回放；这是避免历史记录膨胀的有意取舍。
4. 复制降级依赖 `document.execCommand('copy')`（已废弃但兼容性广）；非安全上下文或浏览器拒绝时提示手动复制。
5. 真实浏览器前进/后退、读屏器播报与 200% 缩放仍属人工验收项，未因本轮自动化通过而关闭 P0。

## 6. 后续建议

- 若需要分享 A+ 队列筛选，可沿用同一白名单模式新增参数；不要把自由文本搜索直接写进 URL。
- 若未来引入服务端渲染或多级路由，迁移到 vue-router 的 history 模式，保留现有 URL 约定作为兼容层。
